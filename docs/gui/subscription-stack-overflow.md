# Windows 订阅更新栈溢出排查

## 已核对的发布证据

- 官方版本：`v0.0.2-rc.202610130655`，源码提交 `b7036222496b4892c2f5c8ad559afbab18768382`。
- 用户提供的 SHA-256 `4e97527e6050215a1bc303d4b94fc095b75ad696d2b72edc66ff2ef07e84567b` 对应官方 NSIS 安装包，不是包内 `gui.exe`。
- NSIS 与 MSI 内程序的 `.text` 相同，PE 时间戳均为 `0x6acdd7ce`，与事件记录一致。PE 指定的默认线程栈保留量为 1 MiB（新建线程可以另设栈大小）。
- `0xc00000fd` 是栈溢出。偏移 `0x19b03c7` 位于栈探测例程；它自身不能还原调用栈或证明业务函数。
- 发布二进制的共享 Tauri 命令入口申请 364568 字节栈帧。通过命令字符串比较分支确认，`gui_set_proxy_mode` 分支进入的 Release 响应派发链还包含 723328、1446656 字节栈帧。后者单独已超过默认栈保留量。
- Tauri 2.11.2 的 `ipc/mod.rs` 在 Debug 中装箱响应任务，而 Release 直接将具体 Future 交给泛型派发。仅通过 Debug 测试不能覆盖这一差异。

以上确认发布物存在栈风险，但没有用户故障进程的转储，不能把代理模式分支断言为那一次订阅点击的实际调用栈。macOS 与 Windows 的 Future 布局也不能等同。

## 客户端处理

- 在订阅 IPC、下载与配置发布、接管配置应用之间装箱较大的异步状态，降低状态按值嵌套和派发时的栈复制。
- 对已确认的大型代理模式命令分支也隔离异步状态，避免它继续撑大共享入口。
- 普通 URL 订阅保持原有 `targetProxyConfigId` 关联和后端配置事务。前端同步成功后只刷新视图，不再次尝试开启 TUN。
- 同步返回错误时恢复该订阅原有规则集目录。提交和恢复均只替换自己的命名空间，保留其他订阅和手动规则的并发更新；保留不可变 ZRS 产物文件。

没有扩大线程栈、捕获栈溢出后继续运行、关闭证书校验或修改内核。

## 回归边界

`subscription_refresh_on_windows_sized_stack` 在独立子进程的 1 MiB 线程栈内，使用真实 HTTP、base64 配置解析、31 个有效 ZRS 下载与验证、规则组合和配置持久化。覆盖首次 200、后续 304、活动关联配置变化、依赖失败使用缓存、发布拒绝以及缺少新依赖时拒绝发布。

原生内核发布使用测试替身；该测试不能证明实际 Windows WebView 调度、运行中连接连续性或用户故障已经消失。Future 大小预算同时覆盖生产 IPC 函数。Windows CI 增加 Release 回归，避免只检查 Debug 分支。

进程在多个持久化步骤之间被强制终止的恢复，以及原生 Windows 安装包的现场点击复验，仍需单独验收。
