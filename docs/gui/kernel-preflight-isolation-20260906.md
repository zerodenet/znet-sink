# 内核安装预检查隔离修复

## 问题与修复

旧内核的 `validate` 命令会实例化运行时，读取相同配置时与正在运行的内核争用 Fake-IP 状态锁。安装事务先预检查、再停止旧内核的顺序是正确的；锁归运行内核正常所有，不能通过删除锁文件解决。

客户端为每个候选子进程设置独立的 `ZERO_DNS_STATE_DIR`，临时目录保留到进程退出并回收后才清理。仍然传入原配置路径，保证相对规则、证书等资源解析不变。进程超时处理、版本匹配、托管生命周期能力检查和失败时保留当前内核继续生效。

预检查输出设置 `NO_COLOR=1` / `TERM=dumb`，并复用客户端日志的 ANSI 清理函数，避免旧内核忽略颜色环境变量时把控制码显示在错误弹窗中。

内核仓库同时将 `zero validate` 改为独立校验路径，保留结构、构建能力、目标计划、路由文件和 DNS 参数校验，不再启动 Engine / Proxy 或打开运行时持久化。客户端临时目录仅作为旧版 Fake-IP 的兼容防护。

## 验证

- 客户端完整 Rust 测试：477 通过、4 忽略；包含并发预检查目录隔离与退出清理、版本命令失败、超时、输出上限、中文颜色码清理、原配置相对资源保持。
- 内核专项测试：4 通过，覆盖运行内核持锁时校验、端口占用、配额状态不读写、相对规则资源与无效配置拒绝。
- 本机当前配置：新内核校验成功，原内核继续持有原 Fake-IP 锁。
- 本机旧内核兼容验证：私有 DNS 状态目录下校验同一配置成功（约 1 秒），临时目录清理成功。
- CI：客户端 Linux/macOS 增加预检查测试，Windows 继续执行完整 Rust 测试；内核三平台矩阵增加专项测试。远端结果以对应提交 CI 为准。

这项修复不更改用户配置、Fake-IP 映射、TUN 或当前运行内核。
