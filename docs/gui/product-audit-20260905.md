# 2026-09-05 客户端首个稳定版产品核查

当前仍为候选版本。本记录按产品入口、状态迁移和失败路径核查，不以用户已报告的问题数量作为范围。代码确认、故障注入测试、浏览器夹具、原生进程测试、安装后真实联网是不同证据等级。

## 本轮新发现及处理

| 操作链 | 发现的触发条件和影响 | 本轮处理与证据 |
| --- | --- | --- |
| 配置编辑、激活、删除后替补 | config.apply 被拒绝或回复丢失时，原实现保存候选并兜底重启，可能打断原本可用的连接 | 移除三个隐式重启分支；公共 config_apply 路径在提交前后核对实例及配置版本；故障注入覆盖拒绝、超时、断连、换实例和新版本覆盖 |
| 规则/全局/直连模式 | 先保存模式再尝试生效；公共规则开启时强制重启；失败后可能保存状态与运行状态不一致 | 使用配置编辑的确认路径；普通模式切换热应用，只有显式 restartCore 才重启；保留导出和错误恢复 |
| 重启、启动偏好、路径设置 | autoStart=false 时修改路径会停止手动启动的内核；部分重启分支遗漏 TUN 恢复；旧配置没有 enabled 时丢失接管意图 | 运行实例与下次启动偏好分开；重启前读取旧 TUN 意图，重启后核对健康恢复；停止状态不查询不存在的 IPC；新增意图及恢复测试 |
| 本地代理端口与系统代理 | 保存地址/端口只改设置，运行监听和系统代理仍指向旧值；配置自定义入口在 UI 却显示默认值 | 有效配置投影更新受管入站并重定向受管系统代理；自定义入口显示真实值和编辑位置；端口拒绝 9000bad 等部分数字；Rust 投影与两项浏览器测试 |
| 公共规则、订阅依赖 | 缺失 provider/ZRS 时删除相关规则后继续成功，包括 REJECT；嵌套引用未完整检查 | 拒绝不完整候选，保留源规则；缺失 provider、下载失败无旧产物、嵌套引用均有回归 |
| Clash 规则转换 | 不支持的类型、目标或额外参数通过 filter_map 静默消失；错误 MATCH 可能退到其他默认出口 | 明确报第几条规则无法转换；支持范围写入 subscriptions.md；不会将丢失规则的候选应用成功 |
| 应用更新全过程 | 下载时检查/切换版本可能释放正在使用的资源；重复安装没有互斥；新选择失败可能保留旧包；安装后重启失败被当作可再次安装 | 统一 busy 状态；选择失败清除旧候选；保留已安装待重启状态，只重试重启；真实服务注入原生 API 的 7 项测试 |
| 更新状态显示 | 无效更新清单被当作已是最新；未检查也显示已是最新 | 错误、未检查、最新、待重启分别显示；加入 CI 更新服务回归 |
| TUN 开关确认 | 仅 enabled=true 就返回开启成功，未检查 healthy；异常状态也可能被丢失回复后的核对当作成功 | 开启及补查同时要求 healthy，配置自主管理分支同样检查；新增 3 项服务行为回归 |
| 诊断导出 | 凭据键采用 camelCase 时未匹配下划线规则，如 privateKey/accessToken | 统一键名匹配并递归脱敏；新增嵌套凭据测试。该测试不代表任意自由文本凭据都可自动识别 |

## 稳定版剩余阻塞

- 中断内核升级的自动续回退及其故障注入。
- 配置、订阅产物、磁盘导出和系统代理跨资源提交，在持久化失败、权限拒绝及进程中断时的完整恢复证据。当前部分历史回退调用仍是尽力恢复，本轮未把它们宣称为原子事务。
- 绑定同一客户端/内核候选摘要的四平台 installed-e2e，特别是网络切换、休眠唤醒、升级中断和退出清理。现有 140 项记录保留未取得的证据，不能直接发布 stable。

这些属于工程侧验收责任，不以用户逐个点击发现为前提。后续修复按以上失败路径推进；每个新增提交都须重跑受影响回归，取得安装证据后再关闭相应用例。
