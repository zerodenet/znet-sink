# 配置工作区：本地保存与来源保护

普通工作区属于客户端配置领域，使用现有 Zero schema、组合链和 SQLite 持久化。
它不新增手机配置方言，也不以本地保存代替运行配置或 VPN 确认。

## 材料及来源

snapshot 先核对来源归属。插件托管、受保护或没有普通正文的来源只返回元资料及原因，
不返回来源、覆盖、最终配置正文；普通编辑入口不能据此取得写权限。plan、validate、
save 和 apply 再核对当前来源，旧面板不能绕过变化后的归属。

普通来源以 JSON 文本传给 Rust；Rust 生成来源、覆盖及合成视图文本。浏览器解析只作
语法和对象根值检查，其结果不参与提交或格式化；u64 最大值不经过 JavaScript number
往返。Rust 使用实际 `RuntimeConfig::parse` 校验 schema、结构及引用，保存原 Value，
不把 typed schema 重新序列化为一份删减配置。格式化也由 Rust 完成。

原生校验错误保留实际错误类别对应的父字段及可用行列，缺少精确路径时使用根位置，
不猜测字段。通用消息不回显配置、凭据或任意 parser 原文。本地 schema 通过不代表
运行内核已编译相同协议，运行兼容性仍须真实预检。

## 纯本地提交

本地保存固定完整来源和关系图、AppConfig、规则集摘要、两文件持久历史 token、
关系 epoch、宿主 session 及客户端 scopeGeneration。
SQLite 发布时按一致锁序核对这些条件，并在同一代次 fence 内完成本地持久化及内存
发布；失败恢复仅针对本操作仍持有的关系，不能覆盖后来的修改。

保存保留当前本地代理运行归属，不 retarget、不 apply、不重建 TUN，也不为返回回执
查询 IPC。成功回执是“已保存，待应用”；重开本地材料仍不能生成一份运行确认。
只读合成视图在未确认时是本地候选，不能称作已提交的运行配置。

## 草稿、预检及原操作

外部更新或配置/实例变化保留脏输入，使旧预检失效并说明冲突。明确放弃后才刷新正文；
晚到的读取、校验、保存或操作回执只属于原编辑版本，不能覆盖新输入或新来源。

运行预检固定来源、客户端覆盖、规则、合成候选、实际运行身份及期限。应用只接受原
plan ID，未知结果只核对该 ID 的回执，不能用旧的相同 digest 回执确认新操作，也不能
重新生成计划来重放原请求。真实运行确认与本地发布是两个阶段；部分成功分别记录。
捕获参数也保存完整冻结Value，重新解析后须在副作用前逐值匹配，不能在改变TUN后
才用摘要发现范围变化。提交与TUN协调固定原物理连接，并在第一次副作用及配置命令前核对原实例/revision；
只从实际确认的配置回执推进预期revision，不从后来的运行快照采纳新基线。保持现有
TUN能力租约、15秒命令响应预算、DNS释放和Windows宿主依赖准备。仅路由变更的快速
路径同样核对实际已启用TUN与冻结参数，并在配置回执后重新读取，不能把本地参数
直接冒充实际设备。纯本地冻结参数不匹配会明确拒绝并允许重新预检；已发送命令或
晚到身份变化的未知屏障保留。工作区没有取得
原运行配置材料的权威快照时，失败不自动把本地旧材料apply回去或重建旧TUN；旧的
通用调用补偿行为保持独立。客户端核对不新增 Zero 远端 config
命令的原子前置条件，相关 CORE-03 边界仍保留。

原操作与未知屏障现使用 SQLite schema 5 持久化，保留 schema 4 的既有历史。副作用前保存原候选和阶段；
`prepared`、`submitted_unknown` 没有真实运行回执时不能凭当前 revision 补造成功，
也不恢复可执行计划。真实运行确认先持久保存原回执，再分阶段完成本地关系、
AppConfig 确认及最终墓碑；跨文件不声称原子事务。完成后清除候选正文并退役对应
内存屏障，其他未知操作保留。旧版从未持久记录的内存请求不能据此重建。

来源关系使用持久单调 epoch，预检即固定其值；数据库写入后 A→B→A 也使旧计划失效。
每个宿主另有安全随机会话身份，本地代次数重置不能使旧计划复活。原正常应用保留
预览时的会话和代次；途中变化只保存历史事实，不自动重绑。原回执时间遇系统调时
保留原值并标注，不用时间顺序代替权威身份。

进程恢复后，界面提供“检查原操作恢复”，不自动补完或重放。只有普通当前来源、
持久阶段、epoch、关系、设置、规则、合成及接管摘要和原运行实例/revision 均匹配，
才能取得绑定新宿主和当前代次的短期单次票据；用户确认后只发布原候选，不 apply、
下载、retarget 或操作 TUN。票据用进程单调时间到期，界面的本地时刻仅作说明。
真实运行已确认而本地发布未完成时保留 `runtime_confirmed_pending_local`；
运行实例已换代或原回执未持久保存时仍不能完成，不声称回滚或当前生效。

AppConfig 与规则集保留独立文件边界，旁置历史元资料与跨进程锁。新记录固定随机
store 身份、文件身份及单调 epoch；正式保存、备份恢复和规则写入都会推进历史，
本版协同 writer 写回同值也不能满足旧 token。预留、纯本地保存和各恢复发布阶段
均在持有文件 guards 时核对原 token 及实际完整 typed 值，不从新值摘要补造历史。
工作区不改变设置时仅确认原文件事实，不重写相同 AppConfig，也不解除已有运行归属。

文件写入与历史确认不是跨文件原子事务。未知写入保留 pending，不自动重写、采用
新 owner 或补造运行回执；领域拥有原操作证明时只能确认精确匹配的原 owner 历史
元资料。旧 tokenless 工作区记录保留阶段和原回执供历史查看，不能借当前 token
取得本地完成资格。新显式核对票据只授权原候选的本地完成，不恢复旧计划执行权。

该保证限于本版协同 writer；首次 legacy 登记不证明之前的历史，未观察到的旧客户端
或外部同值回写、恶意整体回滚不在完整检测范围。预算、文件故障及各阶段边界详见
[存储说明](storage.md)。[本地恢复记录只读检查](recovery-storage-inspection-v0.0.3.md)
不读取候选正文、不清账，也不授予完成许可。手机原生运行所有权与真机恢复仍需单独验收。

## 工作区重启仍需适配

工作区保留需要重启的影响和具体不可用原因。本批不再调用“先写来源，重启失败后
无条件整表恢复”的旧链路；内核管理中的普通重启仍是独立操作。

现有启动流程使用非秘密 bootstrap，再从当前 state 组合并 runtime-only apply；
它没有向工作区返回冻结材料的启动回执，watchdog 也重新读取当前材料。固定版本内核
另明确拒绝 live apply 修改 `api.control` 和 `runtime.principal_quota_state_path`。因此不能把
普通重启之后的热应用当作这些启动字段已经生效。

后续客户端工作包括冻结启动材料、局部 launch snapshot、真实 PID/readiness、运行
回执、本地 CAS 及 watchdog 窗口。普通来源的受限安全启动材料通道尚未实现和验收；
若受保护材料或具体平台确需通用 core 接口，再单独协调，不能将所有重启归为 core 阻塞。
当前提供明确本地保存路径，不将缺回执降级为导出临时配置兜底。

完整证据与后续客户端、core 确认范围见[冻结启动材料与真实启动确认边界](frozen-startup-boundary-v0.0.3.md)。

独立客户端实现必须使用专用 owned frozen-start，不能调用当前普通 restart：
`runtime_host/start.rs` 准备空 bootstrap，`runtime_host/spawn.rs` 在精确 child
readiness 后调用 `core_config::apply_active_runtime`，该路径会重读当前活动材料。
专用入口需要私有、排他创建并验证摘要的启动通道、Unix 权限及 Windows ACL，
持久 pending 窗口还须约束 watchdog 与自动启动。现有 `write_core_config` 的
`fs::write` 和普通导出路径不提供这组保证。

冻结 JSON 也不等于冻结依赖字节。固定 core
[`application/run.rs`](https://github.com/zerodenet/core/blob/e74561f99acca941bfadf0d33e35a5ef08f34086/src/application/run.rs)
在创建 Proxy 前预取 URL 规则缓存；
[`RuntimeConfig::load_from_path`](https://github.com/zerodenet/core/blob/e74561f99acca941bfadf0d33e35a5ef08f34086/crates/config/src/model/mod.rs)
使用配置父目录解释相对凭据、状态与产物路径。未来入口必须封存实际依赖并保留路径
语义，或明确拒绝未封存范围；不能仅凭 typed 规则摘要、child 健康或一次热应用
宣称冻结启动成功。受保护材料保持原授权与 opaque 边界，不降级落普通文件。

验证结果及准确提交 CI 见[验证记录](../verification/mobile-client-v0.0.3.md)，剩余平台
与真机条件见[验收账本](mobile-acceptance-ledger-v0.0.3.md)。
