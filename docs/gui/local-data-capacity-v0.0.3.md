# 本地记录容量与保留预算

`gui_local_data_summary` 是宿主主窗口的只读元资料接口，不需要 VPN 或插件权限。
日志、完成连接历史与捕获帧分别在原存储锁下读取固定文件的 metadata；不读取正文，
不旋转、修复或清理。十进制字符串传递字节和时间，读失败返回 unavailable/null，
真实不存在的文件才计为 0。符号链接、越界或非普通文件拒绝计量；界面不接收路径或原始错误。
各范围独立采样，不保证跨文件系统原子快照，刷新失败保留带采样时间的过期事实。

预算直接复用实际存储实现，不由 UI 再声明一套限制：

| 范围 | 实际策略 | 限制 |
| --- | --- | --- |
| 日志页记录 | `persisted_limit(app.logs.max_entries)`，最少 5000 条，追加批次轮换 | 没有固定字节与时长上限；内存展示上限与磁盘条数不同 |
| 完成连接历史 | 10000 条、32 MiB、30 天；追加及读取轮换 | 容量采样不触发轮换，可能观察到尚未轮换的文件；不代表完整网络历史 |
| 捕获帧文件 | 1 MiB 文件段，当前段加 4 个历史段 | 5 MiB 是保留帧文件预算，不是单次诊断捕获额度；没有固定保留时长 |

容量不包括配置、订阅、授权、工作区/Packet 恢复账本、捕获恢复账本、内核文件日志
或已导出的诊断材料。三个既有清理入口仍分别确认，捕获清理协调写入并停止捕获；
完成后重新读取容量，不把统计采样当清理回执。此批没有增加单条记录删除、导出目录逐项
管理或统一的可配置保留策略，这些仍是 CLIENT-09 的后续工作。

验证包括真实文件 metadata/符号链接拒绝的 Rust 测试、无损与畸形 DTO 测试，及 320px
浏览器中的真实零、未知、过期和固定清理范围检查。浏览器 fixture 不代表手机存储验收。
