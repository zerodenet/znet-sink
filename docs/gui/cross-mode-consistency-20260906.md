# 简约与专业模式一致性

日期：2026-09-06。状态：本地源码变更，尚未发布或替换已安装应用。

## 设计约定

两种模式共用运行数据、已确认设置和错误含义。专业模式展开更多控制和诊断，简约模式保留原有电源环、代理模式与配置来源布局。

本轮采用“切换只改变展示”的约定：进入简约模式不再自动补开 TUN 或系统代理，切换前后的接管状态保持一致。简约电源在完全关闭时同时开启系统代理与 TUN；已有任一路径开启，或 TUN 保留了自动恢复意图时，点击电源执行关闭并取消恢复。正常开启、部分开启、状态未知、异常分别展示，不把部分开启伪装成完全关闭。

| 对象 | 两种模式共同遵守的规则 |
| --- | --- |
| 运行状态 | 同一个 `buildOverview` 模型、同一时钟、同一连接与 TUN 快照；过期不视为正常 |
| 代理模式 | 同一确认值和支持列表；等待、失败及回读未确认时保留原选择 |
| 系统代理与 TUN | 开启状态与健康状态分开；状态未知仍保留关闭已知接管的入口 |
| 配置与订阅 | 共用配置集合及变更通知；旧列表响应不能覆盖新读取；激活失败保留当前来源 |
| DNS | 共用 DNS 设置与保存校验；TUN 和 DNS 劫持的依赖不随界面模式改变 |
| 实时速率 | 同一采样源和 10 秒过期界限，过期显示不可用并停止环形流动效果 |
| 累计流量 | 切换界面不重置会话累计；简约“本次”与专业“内核累计”标明不同统计范围 |
| 界面偏好 | 立即切换展示，保存请求按顺序执行，旧请求不能覆盖最后一次选择 |

## 本轮发现并修正

- 简约模式原来没有专业模式的过期保护、支持模式限制及完整操作忙碌保护。
- 单一路径开启时，简约电源会尝试补开另一条路径，托盘却会关闭；现在共同采用已开启路径的关闭语义。
- 简约模式与配置来源控件原先会在命令确认前自行改变选中值；改为受已确认值控制。模式回读未确认会显示错误反馈。
- 快速切换界面时，旧偏好请求存在后完成、后覆盖的问题；现在串行保存，失败不会阻塞后续选择。
- 删除界面切换专用的网络接管补全入口，避免切换展示引发后台网络操作。

## 验证范围

使用真实状态存储和实际的 `OverviewTab` / `OverviewController` 组件，模拟配置/内核适配器边界。未修改 Zero 内核或原生网络实现，未切换本机代理/TUN，也未重新发布版本。

偏好乱序保存与界面切换触发网络操作的用例，均先在原实现上复现失败，再验证修复。浏览器测试还复现了简约模式在请求未确认时错误切换选中项的问题。

验证结果：

- `pnpm verify:frontend` 全部通过，覆盖既有前端状态与交互约束。
- 状态模型 13 项、命令与观察器 15 项、界面偏好存储 4 项通过。
- Chromium 浏览器回归 28 项通过，其中跨模式 6 项覆盖实际简约/专业组件、操作忙碌、过期数据、失败后选中值和会话累计保持。
- 最后一次改动后的 `pnpm check` 为 0 错误、0 警告，`pnpm build` 成功，`git diff --check` 通过。

这些结果验证共享前端的状态与交互约束，不代表 Windows、Linux、macOS 三个平台的真实 TUN 网络流程已经重新验收。
