# 普通来源的路由规则覆盖编辑

本批提供 PRD V3 A10 的原生 `route.rules` 编辑、排序和启停，以及仅本地保存的完整流程。
入口位于现有“路由与规则集”页面的“路由规则”分段；原规则集管理继续保留。
它不表示 A10 的规则集引用迁移、A13 的 DNS 引用迁移、完整移动端或真机运行已经完成。

## 来源、文本与覆盖归属

读取和修改均先检查来源归属。插件托管、受保护、没有普通可读正文或不支持的内核
只返回身份及原因，不把配置或规则正文放入普通编辑 DTO。普通订阅的原文保持来源归属；
本入口保存的是该配置的客户端规则覆盖，不回写订阅、来源路径或规则集产物。

规则列表来自真实原生配置；没有规则时显示空列表，不生成默认规则或默认出口。
每条规则以 `ruleJson` 字符串在 Rust 与页面之间传递。页面不执行
`JSON.parse → JSON.stringify`，规则字段、嵌套条件和 u64 不经过 JavaScript number 往返。
校验与持久化保留原 JSON 值，不把 native parser 填默认值、规范化或 materialize 后的
配置重新序列化为来源。无损不承诺原空白、键顺序或逐字节格式不变。

覆盖保存在 `AppConfig.profileEdits[profileId].routeRules`，不提升为全局 `clientEdits`。
元资料包含版本、完整来源摘要和有序行；行 ID、启停标记属于客户端管理数据，
不发送给 core。投影只把启用行的原生规则放入 `route.rules`；停用行继续保留在覆盖中，
并且同样必须通过原生结构和引用校验。保存空列表表示明确覆盖为空，
“恢复来源规则”则删除该配置的 `routeRules` 覆盖，两者不是同一操作。

## 编辑、预览与本地保存

| 接口 | 输入及结果 | 边界 |
| --- | --- | --- |
| `gui_route_editor_snapshot` | `profileId`、可选 `fromSource`；返回行文本、来源版本、目标资料、只读或过期原因及 opaque binding | 普通查看不取得运行控制权；受限来源没有可写 binding |
| `gui_route_editor_preview` | 原 `profileId`、binding、完整 rows、`replace` 或 `restore_source` | 固定本次全部行、顺序和启停状态，不随后台变化扩大目标 |
| `gui_route_editor_save` | 原 `planId` | 只保存预览候选，不接收新的行集合，不调用运行内核 |
| `gui_route_editor_status` | 原 `planId` | 只读核对原操作，不补发保存或生成替代计划 |
| `gui_route_editor_discard` | 原 `planId` | 释放未提交预览；结果未知的原操作不能据此清除或撤销 |

接口受宿主主窗口和客户端交互准入约束。预览最多保留四项，每项有效期五分钟，
使用宿主单调时钟控制有效期；界面时刻只作说明。单份规则覆盖最多 1000 行，
相关文本及元资料受 16MiB 字节预算约束；行 ID 有固定长度及字符限制。

添加、编辑、删除、上移、下移和启停先修改草稿。预览展示本次完整集合；
用户明确确认后才发布本地覆盖。关闭确认继续编辑，取消预览不改变来源或覆盖。
有未保存修改时，离开、切换规则集分段或刷新先提示保留或放弃。
运行中的本地提交不会因离页被撤回，也不会在晚回执到达后自动导航。

本地提交绑定完整 profile/subscription 关系图、SQLite 持久 epoch、AppConfig 与规则集
摘要及文件历史 token、原宿主会话、客户端 scope 和 `scopeGeneration`。
提交时按一致锁序核对内存与实际 typed 文件，并在原代次 fence 和关系 epoch 约束内
执行本地写入与发布。返回前还核对原 owned 写入的实际 `receipt.after`、候选设置、
关系、规则历史和宿主代次，再从这份固定上下文构造回执；后继 writer 的新值不能
冒充原操作的成功结果。文件历史用于识别本版协同 writer 的 A→B→A；
不能宣称检测到未观察的外部同值写回或恶意整体回滚。

来源或覆盖变化会使预览失效。不能因为当前正文摘要后来相同，就复用旧文件历史、
宿主或配置代次。保存不改 profile 来源正文、订阅关系、全局 DNS、其他配置覆盖或
本地代理运行归属，也不为返回结果查询 IPC。

## 校验与依赖边界

编辑器使用固定版本 Zero 的真实原生规则及配置 schema 校验引用和有效字段，
不引入第二套路由匹配器。规则目标来自当前原生配置允许的出站、组及其他原生目标；
未知或被移除目标不得静默换成第一个节点。`condition`、`action`、`mode` 等原生字段
由完整 JSON 编辑保留，不把不支持的原型字段伪装成可运行能力。

本入口复用[受限原生文本校验](profile-editor-lossless-v0.0.3.md)：先 typed 反序列化并
检查依赖，再调用 native parser。固定版本 parser 会编译路由及 DNS，因此非空
`route.rule_sets` 和声明的 `route.geoip_database` 会在文件读取前被明确拒绝；
URL 规则集的缓存路径也不能绕过授权。此限制适用于整个来源，而不是只检查可见规则。
拒绝保留材料，不删掉依赖、降级匹配条件、代为下载或当作通过。

校验通过仅说明受支持材料范围内的原生结构和引用有效，不证明 TLS 或凭据可用、
实际构建包含全部协议、公共规则产物完整、平台 DNS/TUN 已接管，或目标可达。
错误使用固定安全说明，不回显原生 parser 中可能出现的路径、URL token 或正文。

## 来源变化、恢复与运行应用

覆盖绑定完整来源摘要。来源更新后，旧覆盖不能自动套用；页面保留旧材料供核对，
普通刷新仍显示旧覆盖的过期状态，须明确“使用当前来源重建草稿”后才能重新编辑、预览和保存。
重建只准备新草稿，不立即改已有覆盖。恢复来源也必须预览确认，
只移除原配置覆盖，不删除来源，不复制另一配置的选择。
页面重新挂载及核对原操作前，会先只读检查当前选中配置和原 binding；
变化或读取失败使旧编辑资格失效，保留草稿与原未知操作，不自动读新正文替换输入。

所有正式配置组合入口须消费同一投影：启动、显式应用、配置切换、订阅更新及
工作区候选不应各自重建规则。来源发生归属变化时仍须重新准入，
不能只在编辑页面阻止读取，却允许运行组合继续消费旧普通覆盖。

成功保存返回 `saved_pending_apply`，表示本地材料已保存，运行状态尚未确认。
用户另行进入[配置工作区](config-workspace-local-v0.0.3.md)预检、确认和应用；
不能把本地保存、进程 Running 或列表选中标识当作运行生效回执。
本入口不启动、重启、下载、apply、retarget 或操作 TUN/VPN。
旧 `profile_settings_apply` 不接受 `routeRules` 写入或恢复，不能借通用设置接口
绕过专用预览或触发即时应用。

提交失败或回执丢失时保留草稿及原 plan ID。已进入发布而结果不明时，
界面进入 `submitted_unknown`，只核对原操作；不自动重新预览、换 ID 重放、
恢复旧设置或补造保存成功。编辑器原计划及状态保留于宿主进程内；
状态读取只返回该宿主已经保留的阶段和回执，不以当前文件值反推原写入成功，
也不提供“补完本地保存”授权。
进程重建不凭旁置文件历史 owner 恢复可执行计划或推断原请求成功。
持久文件事实及其 pending 状态仍由正式文件历史机制处理，不能靠关闭页面清除。
