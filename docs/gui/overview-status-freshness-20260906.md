# 概览运行状态过期误判修复

日期：2026-09-06。受影响客户端：`0.0.16-rc.202609060937`，原生构建号 `360`。
本记录对应源码修复；本机安装的 RC 尚未包含这些变更。

## 现场与原因

本机客户端托管的 Zero 进程仍在运行，父进程归属正确，监听端口为 `7890`。
通过该实例控制套接字执行只读状态查询约 14 ms 返回，并观察到活动连接及持续更新的流量查询。
这证明进程和控制接口可用，不代表所有网络目标均可访问。

概览把超过 15 秒的连接快照标记为“状态待确认”，但客户端初始化后主要依赖内核状态变化事件刷新该快照。
内核持续正常运行时，普通流量不会触发状态变化事件。现场日志中，流量查询持续至 18:36:18，而运行状态查询停在 18:34:54，已超过过期阈值。
内核卡又把状态过期作为无条件禁用按钮的依据，因此正常运行一段时间后会同时出现待确认提示和无法点击重启。

原有测试使用固定的新鲜快照，浏览器用替代卡片模拟重启按钮，缺少时间推进和真实组件验证。

## 修复

- 客户端可见时每 5 秒读取连接、模式、策略组和 TUN 状态；窗口重新可见或获得焦点时立即刷新。隐藏时暂停，慢查询不堆叠，销毁时停止观察。
- 启动、重启、连接、断开、系统代理/TUN/模式/策略切换期间，定时观察让位于命令自身的回读。操作结束后恢复；过期的进程过渡状态不能让观察永久暂停。
- 保留查询失败和快照过期提示；已确认由客户端托管的运行进程仍可重启，忙碌期间及外部内核继续禁止该操作。
- 连接和模式查询增加返回顺序保护；命令确认使之前的读取失效，避免旧结果覆盖已完成操作。简约模式关闭 TUN 后同步更新保存的开关意图。
- 逻辑位于各平台共用的前端状态层，没有修改 Zero 内核和平台网络实现。

## 验证

- 新增 7 个真实状态存储回归用例；在修复前源码上全部失败，修复后全部通过。覆盖超过 15 秒的稳定运行、窗口隐藏/恢复、重复初始化、慢查询、查询失败恢复，以及命令与旧查询交错返回。
- 概览模型和命令测试共 24 项通过；TUN 恢复测试 11 项通过，跨模式状态回归通过。
- Chromium 中挂载实际 `CoreStatusCard` 的概览交互测试 8 项通过，覆盖过期状态下的重启入口、忙碌保护、外部内核保护和布局。
- `pnpm check`：0 个错误、0 个警告。

## 稳定性与 DNS 依赖复核

后续检查增加了“定时观察不提交操作命令”和“操作期间暂停、结束后恢复”的断言；暂停用例在补充保护前失败，修复后通过。最新概览模型与命令测试共 25 项通过。

这轮源码差异没有修改原生启动/重启、系统代理、TUN 路由、配置保存和 DNS 事务。原生状态查询本身包含已有的失效代理恢复逻辑，因此它并非无副作用的纯查询；现有操作锁和进程状态复核保护启动、升级及配置切换，新增定时观察另外在客户端操作期间让位。

TUN 接管流量与 Zero DNS 拦截是两个独立选择：

| DNS 模式 | DNS 劫持 | TUN 行为 |
| --- | --- | --- |
| 系统 DNS（停用 Zero DNS） | 关闭 | 可运行；自动路由需保护系统 DNS 出口 |
| 系统 DNS（停用 Zero DNS） | 开启 | 无可处理查询的 Zero DNS 后端，应拒绝 |
| Real DNS | 开启 | TUN 的普通 DNS 查询由 Zero 返回真实地址 |
| Fake-IP | 开启 | TUN 的普通 DNS 查询由 Zero 返回合成地址并恢复域名 |
| Real DNS / Fake-IP | 关闭 | TUN 不拦截系统查询，不能据此声称系统已使用 Zero DNS |

系统 DNS 模式不保证全部域名规则可识别；流量嗅探成功时可以补充域名，ECH 等情况仍可能回落到 IP。应用自带的加密 DNS 不属于 53 端口劫持范围。

客户端已有关闭 DNS 时同步关闭劫持、保留 TUN 意图、等待重建结果、失败回滚的事务。依赖由保存与启动校验共同保护，本轮补充界面说明，不强制开启 Fake-IP：DNS 模式“关闭”改为“系统 DNS”，明确保存后影响和运行中 TUN 重建的短暂中断。

本机已安装内核 `0.0.16-rc.202609060636` 的只读 `validate` 检查中，客户端生成的 7 个合约配置，以及额外的 6 个 DNS/劫持组合均符合预期：合法组合接受，停用 Zero DNS 却开启严格 TUN DNS 劫持的组合拒绝。配置校验不能替代实际网络接管测试。

内核 `zero-proxy` 的 `dns_modes` 定向测试 3 项全部通过：DNS/劫持/自动路由组合、系统 DNS 出口无法发现时的严格校验，以及经过 TUN 数据包链的系统 DNS、Real DNS、Fake-IP 真实应答。执行时使用 workspace 过滤命令；目标测试通过后停止了剩余不匹配过滤器的空测试目标启动，不将此记录为内核全量测试通过。

完整客户端 `pnpm verify` 通过，包含 477 项 Rust 测试（另 4 项按原定义忽略）。补充命令暂停保护及 DNS 文案后，重新执行概览/DNS 回归、类型检查和生产构建，均通过；完整 Chromium 交互套件 22 项通过。原生检查仍有已有的未使用导入/可变变量警告，本轮未调整相关平台代码。

本地测试环境为 macOS，以上结果不等于 Windows/Linux 或 macOS 原生 TUN 提权接管已重新验收。特权网络用例需要隔离环境，不在当前正在使用的网络上执行，也不据此宣称首个稳定版本已经通过全部平台验收。

本轮未发布或安装新包，未重启本机客户端/内核，也未修改系统代理或 TUN。浏览器测试模拟原生命令边界，不能代替安装后原生验收。
