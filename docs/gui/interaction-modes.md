# 交互模式

简约与专业模式只改变界面布局和常驻入口，不构成功能权限边界。两种模式使用相同的配置、内核能力和命令处理路径。

## 展示原则

- 简约模式保留概览、节点、订阅、日志、插件和设置等常用入口。
- 配置、规则、连接、端点及调试页可从相关操作直接打开，不要求切换专业模式。
- 隐藏页被打开时，导航临时展示当前页，并提供返回原页面的按钮；离开后恢复精简导航，不修改用户菜单偏好。
- DNS 设置中的“管理规则集”直接打开规则页，返回后保留 DNS 设置位置。
- 简约设置侧栏默认收起流量接管和高级配置；明确请求这些设置时仍加载对应面板，并临时展示当前设置项。
- 专业模式展示完整导航，仍遵守用户菜单偏好及实际产品编译能力。
- 切换模式、刷新交互面或隐藏菜单不得强制关闭已经打开的页面，也不得自动更改另一种模式偏好。

## 有效交互面

`gui_interaction_surface_snapshot` 继续由 Rust 生成。前端可同步应用精简布局，避免等待后台偏好写入才改变界面。

```json
{
  "key": "ruleSets",
  "visible": false,
  "operable": true,
  "readonly": false,
  "reason": "hidden in lite mode"
}
```

| 字段 | 说明 |
| --- | --- |
| `visible` | 是否在当前布局中常驻展示 |
| `operable` | 真实能力和执行前提是否允许操作，不受简约/专业模式影响 |
| `readonly` | 实际能力不足时的只读状态 |
| `reason` | 隐藏或能力不足的原因；隐藏本身不是操作失败 |

`hiddenMenuKeys` 和端点菜单偏好也只控制入口展示，不撤销功能。内核未声明支持的能力仍不可操作，不能将它伪装成模式限制。

## 命令与运行状态

- Rust 命令不按 `uiMode` 拒绝规则集、配置、连接、诊断、端点或流量统计操作。
- 实际权限、编译特性、内核能力、参数校验、配置事务和并发保护继续生效。
- 配置激活在两种模式中共用同一路径，不要求配置属于订阅。
- 不以模式切换为由启停内核、系统代理或 TUN，不修改已保存的 DNS、规则或其他配置。
- 打开高级功能不自动切换模式；后台交互面刷新不撤销上下文跳转。

## 验证

- 生产展示状态仓库测试覆盖简约模式打开隐藏规则页、返回 DNS 设置、刷新不重定向、明确打开 TUN/高级配置和模式切换保持页面。
- Rust 交互面测试比较两种模式的操作能力，并验证内核不支持的连接操作仍不可用。
- 桌面壳与跨模式契约检查覆盖配置激活和设置面板的展示边界。
