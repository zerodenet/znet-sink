# 本地恢复记录只读检查

工作区与 Packet 原页面提供显式「查看本地恢复记录」。查看只返回可信宿主投影的
固定分类与有界元资料，不增加运行权限、不清账、不归档，也不重放未知操作。
尚未检查、检查中、检查失败、无存储、旧检查结果及元资料可读分别展示。
来源、宿主或客户端代次变化后，晚结果不能覆盖当前检查；原草稿、计划和恢复票据
继续由各自领域管理，不由此面板更改。

## 工作区数据库

`gui_workspace_storage_inspect` 仅允许宿主窗口调用。不要求活动 profile，也不读取
配置或候选正文。独立只读 SQLite 连接启用 query-only、defensive、关闭 trusted schema，
不进入正常的创建、迁移、旧文件导入、权限修复或业务发布路径。

检查数据库及协作文件的普通文件形态和总计 256 MiB 预算，拒绝不安全链接。只要存在
WAL（包括零字节 WAL），就报告 `wal-active` 并停止，不忽略已提交 WAL 内容来读取
主库或补零。没有 WAL 时使用 immutable 只读连接，不在原目录创建或修改 SHM，结束
再核对 WAL 和主文件是否变化；不 checkpoint、不复制整库。SQL
有长度、进度指令、500ms 执行预算和 200ms busy 等待限制。操作系统文件读取不因此
获得硬截止保证。只在同一只读事务内核对应用标识、支持的 schema、非 view/非 generated
列的真实恢复表，最多读取 64 条、每条最多 64 KiB 的元资料。复用正式账本的身份、
阶段、冗余列及回执结构校验；不查询 `candidate_json`。

返回数据库字节数、已读存储版本及可信元资料/待处理数量；不能完成校验时不补零。
SQLite 错误原文、表内名称/目标、路径、来源秘密及任意元资料正文都不进入 DTO。
它不是离线字节级取证，也不保证外部进程没有并发活动；只允许观察到稳定无 WAL 的
主文件。检测文件替换、主文件变化或 WAL 出现时将结果标为历史并要求重新检查。

`metadata-readable` 仅表示上述范围的元资料可读。它不证明候选正文有效、账本其他
页完整、原写入成功或当前内核运行身份；也不产生恢复许可。

## Packet 关闭账本

`gui_packet_ledger_inspect` 只打开已存在的协调标记和有界账本，绝不调用会初始化或
修复记录的写入口。返回固定错误分类、初始化/文件锁状态、字节数，以及完整稳定读取
且不超过 1 MiB 时的 SHA256；仅通过完整结构校验后提供记录数。
原物理目标、operation ID、配置、地址和文件正文不进入该 DTO。

坏 JSON、不可信结构/版本、丢失已初始化账本、缺协调文件、权限失败、锁占用、
容量或持久发布未确认分别可见。宿主安全随机身份缺失仍可查看元资料，但控制继续
拒绝；检查本身不会修复或确认原关闭。

## 恢复与归档边界

损坏元资料可能已无法还原全部原目标和未知副作用。把原文件归档后建空账本会丢失
这些屏障；原文还可能包含敏感材料。因此本批没有提供「清空后恢复」按钮，亦未对
真实用户文件执行删除、归档或迁移。未来如增加证据保存或人工恢复，须独立明确确认、
固定原字节/身份、保留原材料并定义屏障如何继续；归档成功不等于操作结果已确认。

开发测试仅使用私有临时目录，覆盖损坏、权限、锁占用、真实进程重开和检查后屏障
仍在；浏览器使用宿主事实 fixture，不能替代平台运行或真实手机恢复验收。
