# 客户端全局设置

用户直接编辑设置并点击应用；页面不再提供全局优先级选择或六项覆盖开关。
优先级由操作表达：客户端显式设置 > 订阅/导入文件中的值 > 客户端缺省值。
端口、DNS、TUN 参数、测速、UDP 空闲时间、绕过规则和公共规则追加开关作用于所有配置。

例如订阅端口为 7891，页面显示 7891。用户改为 7877 并应用后：

- 只记录 `localProxy.port = 7877`，没有改动的监听地址仍遵循来源。
- 内核配置确认应用后，已开启的系统代理同步指向 7877；原本关闭的代理不自动开启。
- 订阅原文保持不变；订阅更新、切换或导入另一份配置后仍使用 7877。
- 点击“恢复配置值”删除该项全局记录，重新读取当前配置最新值，缺失才使用默认值。
  此后切换配置，端口继续遵循各份配置自己的值。
- 应用失败走原有配置/存储/系统代理恢复流程；提交结果不确定时明确报错，不宣称已回滚。

## 保存与组合

`AppConfig.clientEdits` 保存全局稀疏字段记录，不把整张表单复制为覆盖配置。
编辑器比较本次读取的快照，仅提交变化字段；命令携带配置 ID 并在配置操作锁下
核对活动配置，防止切换后，旧页面以过期来源快照提交设置；ID 不决定设置的作用范围。

监听地址与端口、公共测速地址与策略组容差、TUN 参数各自记录实际修改字段。
DNS 和绕过规则是各自编辑器提交的完整配置块；改动它们不会替换其他能力。
公共规则追加开关同样是全局设置，规则页可恢复来源选择。

来源中的 false、0、[] 等显式值不会被当成缺失。明确的 inbounds: [] 不自动
增开监听器。公共测速地址的本地修改不替换策略组专用 URL；容差未修改时保留
各组自己的数值，修改后统一所有配置各组的容差。

启动、订阅更新、配置切换、导出运行配置以及端口/系统代理/手动测速均使用同一
全局设置组合逻辑。端点启用/方向与策略组选中节点仍属于各份配置，不能串到其他配置。
端点偏好继续保存到 `profileEdits`；删除配置不会移除全局客户端设置。

所有客户端设置入口均遵循这一组合：设置页、通用 `app_config_update`、旧 DNS/TUN
应用命令、配置检查与导入。TUN 的 DNS 就绪检查通过 `client_settings_get` 读取生效
设置，不再只读默认值；DNS 预览和校验使用本次草稿，不会被已保存的 DNS 覆盖。
UI、日志、内核路径、启动偏好与 TUN 开关意图本来就属于全局客户端状态，继续全局保存。

## TUN 与恢复

端口、测速和规则选择走配置应用确认流程。DNS、TUN 和绕过修改复用宿主重启/
恢复事务；原本关闭的 TUN 不自动开启。来源 TUN 参数与用户本地参数组合后只在
用户启用或恢复接管时传给 tun.start，静态配置不会自动接管网络。

普通订阅热更新/配置切换若改变已开启的 TUN 参数，仍要求先关闭 TUN，避免设备
继续使用旧参数却宣称新配置完整生效。真实系统授权与跨平台安装行为需安装验证。

## 兼容

升级时，将活动配置已有的客户端字段一次迁移到 `clientEdits`，不任意选用其他配置
的冲突值。旧按配置保存的记录保留用于恢复，但其网络字段不再参与运行配置合成。
空的 `clientEdits` 表示迁移已完成，恢复后不会再次导入旧记录。没有活动配置时，
只迁移旧全局开关的显式选择。普通默认值不推断为用户修改。
可移植设置 v4 包含全局稀疏字段，不包含端点偏好、策略选择或机器路径；旧 v1/v2/v3
设置仍可读取。导入校验字段与值，再复用现有应用/恢复事务。
旧客户端曾经删除的来源 DNS 无法自动还原，需要重新同步订阅或导入原文件。
