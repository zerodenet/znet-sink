# 配置优先级

优先级为：用户逐项选择的客户端覆盖 > 当前配置中的值 > 客户端缺省值。
旧客户端保存的设置不被推断为用户同意覆盖。`overrides` 缺失时各项均为 false；
设置 → 网络 → 配置优先级提供逐项开关、来源和解析结果。改变优先级使用现有
重启/恢复事务，可能重建已开启的 TUN，不自动开启原本关闭的 TUN。

| 能力 | 默认行为 | 显式覆盖 |
| --- | --- | --- |
| 代理入口 | 保留来源地址、端口和 tag；缺少本地入口字段时补齐；完全没有 inbounds 时生成缺省 mixed 入口 | 替换主本地入口的地址和端口，保留协议、认证、tag 和其他入口 |
| 公共测速 | 保留 runtime.latency_test_url，缺失才补客户端值；每个 URLTest 组已有 url 优先，缺失继承解析后的公共地址 | 统一公共地址及 URLTest 组地址 |
| URLTest 容差 | 只补缺失的 tolerance_ms，保留 0 | 替换组容差，仍遵循内核能力兼容检查 |
| DNS | runtime.dns 存在时整块保留，包括显式空集合；缺失才使用客户端 DNS 设置 | 使用客户端 DNS；客户端关闭时移除来源 DNS |
| TUN | 来源参数优先；只在用户启用或恢复已开启的 TUN 时合并进 tun.start | 使用客户端参数 |
| 绕过 | route.bypass 存在时保留，包括 []；不将客户端原生代理例外套用到该来源策略 | 使用客户端绕过策略及其 DNS/TUN/系统代理投影 |
| 通用规则 | route.rules 存在时保留，不追加客户端通用规则 | 允许追加用户已启用的通用规则；来源普通规则仍保留 |

不存在和显式值必须区分：false、0、[] 以及无效的显式值都不能被静默替换为
缺省值。无效配置沿原校验路径报错。明确的 inbounds: [] 不等于缺少 inbounds，
不会自动增开代理监听；该配置无法启用系统代理时会明确报错。

客户端的监听设置保持为缺省值，不随切换配置而回写。系统代理启用、配置切换后的
代理重定向、托盘终端代理、启动端口检查和连接操作都通过同一入口解析函数取值。
例如来源 7891、客户端 7890，默认最终监听和系统代理使用 7891。

手动单节点/批量测速显式传递解析后的配置公共测速地址，缺失才使用客户端默认值。
它没有唯一的策略组归属，不任意选择某一组专用 URL。手动策略组测速由内核使用
该组有效设置。手动结果和自动健康状态仍保持各自的语义。

TUN 参数与生命周期分开：最终静态配置不携带 runtime.tun，以免导入/启动内核
直接接管网络；原始来源 TUN 块保留在配置库中，启用时使用其地址、MTU、路由、
双栈及 DNS 劫持参数。IPC、子进程生命周期、系统授权仍属于客户端宿主。
修改被来源接管的客户端 TUN/DNS 缺省值不会重建来源 TUN 或替换来源 DNS。
热切换或更新若改变已开启的 TUN 参数，会在发布前拒绝并提示先关闭 TUN；重新开启
后采用新参数。本批不把配置应用成功误报成设备已经按新参数重建。

来源 DNS 不再在启动迁移或配置发布时删除。旧版本已经删除的来源 DNS 无法从
当前客户端设置可靠还原，需要重新同步订阅或导入原文件。旧生成入口已写入来源
后同样视作现有配置，不根据 tag 猜测用户意图。

可移植设置格式升级为 znet.client-kernel-settings.v3 并携带覆盖选择，兼容导入
v1/v2（未提供覆盖选择时默认配置优先）。旧版本会拒绝 v3，避免忽略覆盖选择。

来源表是已保存设置的解析预览，不宣称运行中的内核已采用它。组合报告仍记录实际
改变路径；应用事务和运行状态回读负责确认生效。订阅更新、切换和启动共用组合边界。
