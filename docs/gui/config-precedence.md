# 客户端配置优先级

客户端保存的能力设置高于订阅和导入配置中的同名能力。本次能力覆盖不回写已保存的来源内容；组合器在副本上生成发送给内核的最终配置，订阅原有的格式转换和入口补齐流程保持不变。订阅更新、切换配置和启动内核都使用同一组合边界。

| 能力 | 最终行为 |
| --- | --- |
| 公共代理地址、端口 | 客户端值覆盖第一个可用的 mixed/http/socks5 本地入口；保持该入口的 tag、协议、认证和基于 tag 的路由关联，其他独立监听器保留自己的端口。例：客户端 7890、订阅 7891，主入口最终为 7890。 |
| 公共测速地址 | `urlTest.url` 写入 `runtime.latency_test_url` 和每个 URLTest 组的 `url`。手动单节点/批量测速也显式传这个地址给内核，避免省略参数后使用内核默认值。 |
| URLTest 容差 | 客户端覆盖组内 `tolerance_ms`，包括显式的 0。既有内核版本/能力检查仍决定是否注入该字段。 |
| DNS | 客户端 DNS 设置决定最终 `runtime.dns`；关闭时移除来源 DNS。 |
| TUN | 移除来源 `runtime.tun`，由客户端持久化意图、平台捕获生命周期和状态确认负责启停及参数；不会在导入时让来源配置自行启动 TUN。 |
| 统一绕过 | 客户端规则覆盖 `route.bypass` 专用槽，并投影到客户端 DNS/TUN/系统代理消费者；来源普通 `route.rules` 保留。 |

未设置过公共测速地址的旧客户端配置会迁移为 `http://www.gstatic.com/generate_204`。可在设置的“公共测速与自动选择”中修改；接受有主机的 HTTP(S) 地址，不允许账号密码或 URL 片段。“网络检测地址”仍是本机连通性检测，和这里的代理节点测速用途不同。

保存公共端口或测速设置会沿用配置重组、内核应用与失败回滚事务。内核运行时成功保存后供后续请求使用；不运行时保存，下一次启动组合生效。手动测速结果与自动 URLTest 的策略健康判断仍保持各自语义，统一 URL 不代表手动成功会解除自动健康隔离。

旧 `localProxy.sourceProxyConfigId` 不再锁定输入或让订阅反向改写客户端端口。历史版本已经覆盖掉的用户原值无法可靠恢复，因此保留当前保存的 host/port，由用户在设置中改回期望值。

升级后的第一次重组/重启才会使新优先级进入已有运行内核。若仍观察到旧版本配置托管的 TUN，保持冲突保护，先重新应用配置或重启内核，不能仅凭前端状态对旧设备强制接管。新配置切换不再在提交前主动拆除 TUN；应用确认后由客户端调和其期望状态。

组合诊断中的 `local_listener`、`client_tun`、`global_dns`、`urltest_override` 和 `bypass` 可用于确认哪些路径被覆盖。该报告证明最近一次组合结果，内核是否已生效仍以应用结果和运行状态回读为准。
