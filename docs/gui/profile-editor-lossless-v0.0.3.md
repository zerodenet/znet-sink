# 普通配置的无损文本编辑与本地保存

本批补充 PRD V3 A08 的普通手工配置添加、查看、校验与本地编辑链。它不替代配置工作区、订阅来源管理或显式启用，也不表示 A08、完整移动端或真实手机验收已经完成。原生 VPN、core 接入及宿主运行生命周期仍按已确认范围后置；A10、A18、A19 等独立用户功能继续列于[完成度矩阵](mobile-client-completion-matrix-v0.0.3.md)。

## 文本与来源边界

编辑器不使用旧列表 DTO 中的 `content` 构造草稿，不在 JavaScript 中对配置正文执行 `JSON.parse → JSON.stringify`。列表 DTO 保留原兼容形态，仅用于列表、来源与选择信息；正文由 Rust 专用 snapshot 返回 `sourceJson` 字符串，校验、格式化和保存均传回原文本。

这里的“无损”指受支持配置的整数和有效字段在 Rust JSON 值与文本之间保留，尤其不把超出 JavaScript 安全整数范围的 u64 经 `number` 往返。保存保留原 JSON 值，不把校验器规范化、填默认值或 materialize 后的 `RuntimeConfig` 重新序列化为来源。它不承诺原文件空白、键顺序、BOM 或逐字节格式不变，也不能修复旧链路此前已经舍入的数据。

来源按读取与修改分别准入：

- 普通手工 Zero 配置可读取 Rust 文本并编辑。已有 `path` 不构成重新读取文件或获取同目录权限的授权；本地保存更新客户端材料，不回写来源路径。
- 普通订阅关联正文只读，不能在普通编辑器改写订阅来源；应回到订阅同步或受支持的客户端覆盖入口。
- 插件托管、受保护、缺少普通正文或不支持的来源不得降级为普通材料。托管和受保护正文不进入 snapshot、临时编辑 DTO、错误或日志。
- 文件读取是用户另行发起的动作。桌面使用受能力与预算约束的所选文件读取；移动端使用系统文档适配器返回内容，不把桌面绝对路径或 content URI 当作普通文件路径。选择取消、失败、结果未知或晚到内容不能覆盖后来编辑的草稿。

## 宿主接口

四个接口均受宿主主窗口与客户端交互准入约束；移动布局不继承桌面精简模式的隐藏清单。

| 接口 | 输入及结果 | 边界 |
| --- | --- | --- |
| `proxy_config_editor_snapshot` | 可选 `id`；返回目标、名称、`sourceJson`、只读原因、十进制来源版本、opaque `binding`，新建另返回固定 `createTargetId` | 新建不借用现有配置正文；只读来源不获得可保存 binding |
| `proxy_config_editor_validate` | `{ id?, binding, sourceJson }`；返回校验状态和 Rust 格式化文本 | 不保存、不启用，不读取未经授权的依赖 |
| `proxy_config_editor_save` | `{ id?, binding, name, sourceJson }`；返回 `saved_pending_apply` 与新 snapshot | 没有 `active` 输入；只发布本地材料 |
| `proxy_config_editor_read_file` | 桌面所选路径；返回受限 UTF-8 文本 | 不解析配置、不解析相邻路径；移动拒绝此路径接口并使用系统文档读取 |

`binding` 绑定具体目标，包括新建与编辑的区别，不能跨目标复用。新建 snapshot 的 `targetId` 为 null，`createTargetId` 在提交前固定为该 binding 对应的手工配置 ID；保存仍以 `id: null` 提交，宿主只创建这个原目标，关系或会话变化后旧 binding 不再可用。已有目标的 `createTargetId` 为 null。前端核对新建与编辑的目标形态，保存回执必须指向原有 ID 或原 `createTargetId`；不自行拼接、刷新或猜测 binding。只读状态没有有效可写 binding 时不得退回旧 upsert/import API。

## 校验范围与依赖准入

文本受 16MiB UTF-8 字节预算约束。校验先对原文本执行 native typed 反序列化，再检查文件依赖，然后调用固定 `zero-config` 的真实 parser。typed 反序列化不能改成先投影 `Value` 再反序列化，否则可能擦除原文本中的重复字段错误。

固定 core `e74561f` 的 `RuntimeConfig::parse` 会进入 `validate`，后者调用 `compile_route` 和 `compile_dns_dispatch`；规则集编译可读取文件或缓存路径，GeoIP 编译可读取数据库。因此本入口在真正 parser 之前拒绝非空 `route.rule_sets` 与声明的 `route.geoip_database`，返回明确依赖授权原因。URL 型规则集的缓存路径也不能被当作无 IO 配置。拒绝不会删除字段、清空引用、代为下载或把不完整材料保存为有效配置；原草稿保留。

通过表示来源 schema、字段类型、引用和原生校验在当前受限材料范围内通过。它不证明 TLS/私钥/环境凭据可用、实际构建已编译全部协议、客户端覆盖组合可运行、外部材料已授权，或平台监听、DNS、TUN、真实网络生效。启用仍需走原运行预检和回执链。

错误只返回固定安全说明、字段路径及可用行列位置；不透传 parser 原始错误中的 URL、路径、未知字段值、配置正文或凭据。错误与校验结果都不是运行成功回执。

## 保存与启用是两个动作

本地保存先重新读取并验证原 binding，再校验文本；提交时通过完整 profile/subscription 关系图、SQLite 持久 epoch、host session、客户端 scope/generation、AppConfig/规则集摘要及文件历史 token 的 CAS。保持相关内存锁与实际文件历史锁直到本地提交，不能因为 A→B→A 后当前摘要相同就采纳旧编辑授权。

新配置保存为未选中；编辑已有配置保留原选中状态和归属信息。保存不调用 IPC、运行状态刷新、系统代理 retarget、TUN、下载、启动或重启；也不为相同 AppConfig 制造一次投影写入。本地来源变更使旧客户端观测或控制绑定失效，不等于停止或重新应用内核。

`active` 只表示本地选择关系，不能据此把新保存正文称为“当前生效”。当前已选中的配置仍须有独立、明确的应用入口；用户发起启用才进入既有 profile activation 链，接受真实预检、拒绝、未知或运行回执。原生运行桥未接入时继续明确不可用，不以本地保存补出 VPN 或内核成功状态。

提交失败、版本冲突或依赖准入失败保留名称和原文本，不自动刷新覆盖草稿。提交已经进入持久发布、但最终 snapshot 无法确认时，显示本地保存结果未确认，先由用户刷新核对原对象；不自动重试、恢复旧正文或顺带启用。新建回执丢失时仅按提交前固定的 `createTargetId` 只读核对；不能重新读取新建上下文来替代原目标。读取到该对象只说明当前本地材料事实，不证明原写入已确认，不能解除未知状态或自动重试创建。核对仍保留草稿；之后的新建预览与原请求不同，不能被用作重放原保存。重新读取来源或离开有改动的编辑器时，应先明确继续编辑或放弃；保存与验证的晚回执不得覆盖新目标或新草稿。

## 验证与剩余限制

实现与测试入口为 `configuration/native_validation*`、`configuration/profile_editor*`、`commands/profile_editor.rs` 及对应前端状态、配置页和测试。回归应覆盖大整数、合法高级字段、重复 JSON 字段、未知协议/引用、FIFO 等未授权依赖、托管/订阅只读、来源切换、关系或文件历史 ABA、本地保存不产生运行副作用、取消与晚回执保留草稿、已选中配置保存后仍可明确应用。

本文件只描述生产接口和预期边界，不记录尚未实际运行的通过数。具体已运行检查、CI head、平台与未运行项目以[统一验证记录](../verification/mobile-client-v0.0.3.md)为准。系统文件提供者、Galaxy S8/API24、存储不足及真实手机运行仍有各自验收；四项依赖许可资料缺口保留，不由本编辑功能消除。
