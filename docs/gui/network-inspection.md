# 流量拦截、抓包、HTTPS 调试与改写

2026-09-09。应用层流量检查与改写的目标设计，尚未实现；已有客户端会话元数据记录及本次增量见末节。属于网络工具箱的可选能力族，承接 [模块化与产品组合](./internal-modules.md)。当前先完成内部模块化和稳定性；本文明确后续内核、工具模块与插件的边界，不代表本轮交付了抓包或 MITM。

## 能力拆分

“拦截”包括把流量接入处理链，也包括调试时暂停一条请求等待修改，两者需要不同的资源和完成语义。

| 能力 | 责任 | 独立性 |
| --- | --- | --- |
| 流量接入 | 接收显式代理流量或平台允许接管的流量，保留来源及目标信息 | 由平台适配与内核现有入口协作；不能承诺所有平台接管范围相同 |
| 抓包与观测 | 按范围记录包、流或应用消息，关联时间线并提供有界导出 | 只读观测可单独启用，不要求修改或解密 |
| TLS inspection | 为选定调试目标建立客户端侧与上游侧 TLS 会话，提供应用明文 | 独立可裁剪；保留上游证书验证，证书管理有自己的生命周期 |
| 应用协议检查 | 解析请求/响应、流和帧，建立协议相关的会话模型 | 按协议声明支持范围，不把任意 TCP/UDP 字节都当作 HTTP |
| 改写与模拟 | 修改受支持的消息字段、生成模拟响应、执行声明的处理规则 | 写入路径与只读抓包分别授权、分别启用 |
| 交互式拦截 | 在指定阶段暂停指定流/请求，允许继续、修改或终止 | 有截止时间与并发上限；界面退出后的处理策略必须明确 |
| 分析与回放工具 | 查询记录、比较消息、按用户意图重发请求或复现场景 | 回放是新的执行操作，有独立目标与副作用；抓包记录不自动重放 |

数据包、重组字节流和 HTTP 消息属于不同处理层。网络层修改需要正确处理协议状态；应用层改写需由协议实现维护 framing、长度、压缩及流状态，不开放无约束的字节替换作为通用“改包”接口。

## 内核与工具边界

- **Zero 内核**拥有实时流量生命周期、载荷处理链、协议解析/重编码、转发时序、背压、限额及策略执行。可选能力通过内部职责清晰的库和 feature 装配，不把所有逻辑放进 `zero-proxy`。
- **客户端工具模块**拥有会话列表、请求检查器、过滤、拦截规则编辑、证书操作界面、导出和调试体验。通过类型化控制面和有界载荷读取操作工作，不让每个包经 Tauri/WebView 往返才能转发。
- **未来扩展**区分配置模块、网络处理脚本与客户端工具插件。记录分析器和协议展示器可由工具插件提供；流量脚本的语义执行点归属内核处理链。脚本执行器是否同进程运行或隔离部署，依据延迟、内存、取消和平台要求决定，不预先固定在 GUI 或内核某个进程。Zero 不因此加载第三方原生动态库或引入公开协议 adapter SPI。
- **最小宿主**负责选择模块及管理生命周期、预算和授权范围，不读取或存储所有模块的载荷。

遵循内核已有职责：配置 ADT/校验留在 `zero-config`，查询/命令/事件契约留在 `zero-api`，运行态编排留在 `zero-proxy`，协议语义由对应实现拥有，平台接管由平台/TUN 适配完成。新的应用协议检查职责需要独立归属，不能与 HTTP CONNECT 代理入口的握手解析混为一谈。具体 crate 划分在首条执行链实现时确定。

控制仍沿现有 Zero 控制面扩展，不能借 Connector 建第二套配置/命令 API。捕获正文采用有界流/句柄读取，普通事件仅携带必要的元数据；不把大块或敏感正文塞进默认日志、全局事件总线或 webhook。

## 可组合的执行路径

基础转发路径保持独立。匹配到观测规则时，产生有界记录供异步读取；匹配到 HTTPS 调试规则时，进入可选 TLS 终止和应用协议处理路径。HTTP 请求与响应各有明确处理阶段，不能用一条忽略方向和协议状态的通用流水线代替。

以下三种行为采用不同的完成契约：

1. **旁路观测**：消费者变慢时按记录策略采样、截断或停止记录，暴露丢弃数和原因；不能悄悄拖慢整个转发路径。
2. **在线改写**：适用的静态规则尽量在内核内执行。需要外部执行的处理器只能在授权阶段得到受限上下文并返回类型化修改结果；内核检查范围、版本和协议约束后执行。
3. **人工拦截**：显式暂停被选中的操作，截止时间、最大暂停数量、断开调试器后的继续/终止行为均由该规则声明。

规则声明失败策略。调试规则可选择超时继续原始流量或终止被拦截操作，但必须可观测；承担阻断职责的策略不能因为处理器异常而默认放行。已经发往对端的数据不能声称可撤回或原样回滚，处理阶段和可修改范围必须在接口中明确。

记录和修改携带流标识、请求标识、内核实例及规则版本；过期结果不能作用于复用标识后的新流。大载荷采用有界缓冲/流式契约，不能为了处理正文无限缓存。禁用某能力时清理所属任务和记录句柄，对在途流的行为由执行契约决定。

## HTTPS 调试及数据范围

普通 CONNECT 转发无法直接读取 TLS 应用正文。基于调试 CA 的 MITM 依赖客户端接受相应证书信任；平台、应用信任策略和证书固定可能限制可用范围，不能承诺“开启后解密所有应用”。参考 [mitmproxy 工作原理](https://docs.mitmproxy.org/stable/concepts/how-mitmproxy-works/)与[证书说明](https://docs.mitmproxy.org/stable/concepts/certificates/)。

产品面向用户选择并有权调试的流量。TLS inspection 默认关闭，按目标范围启用；证书安装、信任和移除走平台支持的用户操作，安装应用或普通代理启动不隐式安装根证书。调试 CA 私钥由受控证书组件管理，不通过抓包 API 返回插件；内核到上游的证书验证不能因客户端调试信任而被关闭。

未来扩展接口区分元数据读取、请求头/正文读取、记录导出、请求/响应修改和回放等能力。授权与目标范围、操作和运行实例关联；插件获得分析权限不自动获得外传、改写或回放权限。敏感正文按需保留，容量、保留期和导出位置可控，普通错误日志不打印正文或秘密。面板受保护配置的密钥权限与流量调试权限属于不同边界，不能通过调试接口获得配置密钥或配置回读。

## 自治、裁剪和调试验收

- 可构建基础转发、只读观测、HTTP 调试、HTTPS 调试等不同组合。裁掉 HTTPS 调试时同步移除专属证书签发依赖和证书界面；共享 TLS 出站依赖若仍被其他功能需要则保留。
- 按会话、规则、处理器展示状态、处理延迟、队列深度、截断/丢弃数、超时和错误原因。模块自身调试日志不与被捕获内容混用。
- 测试处理器超时、崩溃、断开、队列满、取消及实例替换；隔离无关流量，用户停用后不自动重新启用。
- HTTP/1.1、HTTP/2、HTTP/3、WebSocket 等支持范围分别声明和验证；支持其中一种不等于支持全部。不能通过静默降级或隐式阻断其他协议伪装覆盖范围。
- 离线解析/展示工具可以不启用实时接管或 MITM。可独立用录制样本、组件替身和失败注入复现处理器问题。

## 客户端会话记录增量（2026-09-11，PR #42）

本批复用已有活动连接投影、完成事件历史文件、筛选分页和清空入口，只补齐客户端排障工作流。Zero 内核、flow 契约、订阅范围和查询频率不变；本批没有新增抓包、HTTP 正文或持续监测任务。

- 连接记录页读取同一次本地分页查询附带的保留总量、筛选匹配数、占用和接收时间范围。现有保留策略为 10,000 条 / 32 MiB / 30 天，先达到的限制生效；仅收到的结束事件进入文件。
- 接收时间筛选与原有搜索、协议、出口、结果筛选在分页前执行。接收时间不是连接起止时间；断线、未运行、保留清理和写入失败都可能造成缺失。不会从事件序号猜测缺失量，也不会将现存最早/最晚时间称为完整覆盖。
- 页面展示本次客户端启动后的清理与写入/维护失败计数，历史累计缺失量仍未知。暂停查看不停止后台保存。
- “导出筛选记录”从本地文件一次读取当前保留范围内的全部匹配事件，不受页面已加载数量影响，也不会向内核补查。导出文件归入既有诊断目录，计入诊断存储统计并可通过既有清理入口删除。JSON 附带版本、筛选、范围、限制及原始完成事件，包含地址/进程/路由元数据，不是通用无敏感信息的诊断摘要。
- 历史去重保留事件提供的内核实例身份，旧记录缺失身份时保持未知。启动时从调试日志和独立连接历史共同恢复 ID 上界，避免短日志清理后影响长历史的分页；列表积压后重新建立连续的分页起点。
- 已有详情查看继续复用。实时视图最多保留 500 条、渲染前 200 条，页面明确提示，不代表全量存档。

实现验证使用临时历史文件和隔离浏览器数据，不启动或修改用户的实际代理/TUN。安装版集中验收仍由 PR #42 的验收流程承担。
