# 工具任务的当前结果与历史边界

DNS、Fake-IP 与路由评估复用原 `ToolRuntime` 的队列、并发预算、持久化和任务 ID。
页面只拥有观测投影，不新增执行队列，退出页面也不取消后端任务。

前端 `ToolJobsState` 先建立独立任务/范围监听，再读取当前 `ClientCoreSnapshot` 和
有界历史。已完成的恢复记录只进入“任务历史”，不会自动成为当前 DNS/路由结果，
更不会因旧 Fake-IP 清理完成而新建缓存查询。当前范围内仍在执行的任务可在页面
重新打开后接收真实的后续完成事件。

配置 ID、无损配置版本和客户端内核代次共同匹配；另核对共享 Rust 客户端提供的
`ClientCoreSnapshot.scopeGeneration`。它仅随配置提交/内核生命周期推进，与会因
probe/普通观测推进的 `revision` 不同，即使界面漏掉中间切换，也能识别 A→B→A。
缺少该字段的旧宿主保留可读历史，不能授予当前任务控制。范围变化、运行来源离线或读取
失败立即清除当前结果；输入仍保留为草稿。路由的旧入站选择失效，不恢复为新配置
的可执行目标。历史保留原范围、时间、状态和已有结果，明确不是当前网络健康。
前端最多保留128项，优先保留活动任务；结果正文只在用户展开对应历史项时呈现。

任务事件和显式启动/停止的结果交付前重新读取当前范围；较旧的范围快照不覆盖
较新的代次。页面内完成事件须属于当前范围且曾被观察为活动，或匹配本页的原启动
回执，才更新当前结果。重复完成不再次刷新缓存；清理后的缓存查询携带原任务范围，
在异步等待期间不能被重定向到另一个配置。晚到启动成功/失败只保留可解释的历史。

新界面始终向 `gui_tool_job_start` 和 `gui_tool_job_cancel` 传原 `expectedScope`
及刚读取的 `expectedClientRevision`，使 RPC 排队期间发生的本地换代也在入队前被拒绝。
入队和取消在 AppState 的同一 client-core 锁下比较，并采用与范围失效一致的
core→ToolRuntime 锁顺序。拒绝发生在新任务 ID/队列分配之前；历史任务不能继续控制。
可选参数保留旧调用兼容，旧调用仍由宿主绑定当时的范围。普通观测恰好发生在读取和
提交之间时也可能拒绝，界面保留输入并要求明确重试，不自动换 ID 重放。

这里的 `ClientScope` 是既有客户端配置身份与本地内核代次，不是 Zero 的远端
原子配置 revision，也不是 iOS/Android 服务已经装配的证明。实际 wire 写命令的
跨控制器条件仍遵守 `CORE-03`，原生运行和生命周期仍按 `todo.md` 后置。

页面每五秒做可见期间的范围观测，focus/恢复可见时重新核对；不会靠该计时器
恢复或调度任务。每个监听和观测计时器在页面销毁时释放，不关闭共享内核事件通道。

验证使用实际生产状态类、实际组件及 AppState 入队/取消边界：恢复的完成历史、
当前活动恢复、profile/完整版本/代次变化、离线、晚到回执、事件先于启动回执、
重复清理、固定范围缓存刷新、订阅迟到释放与历史容量。浏览器夹具不启动真实 VPN。
