# 设置迁移的客户端边界

迁移文档使用 `znet.settings-transfer.v1` 封装客户端允许迁移的字段。
网络值继续使用既有 client settings 和 Zero 原生配置 schema，没有新增移动配置方言。
入口为“更多 → 设置 → 设置迁移”；粘贴 JSON 的校验和保存独立于系统文件能力。
界面操作状态由应用共享的呈现会话保留；离开页面提示未保存草稿，未知结果保留
原 plan ID，返回后可继续核对。这个会话没有业务队列、UI 计时器或原文持久化，
原生后端仍是计划、保存和回执的唯一执行方。

## 导出与输入

导出仅包含主题、日志偏好和显式客户端拥有的白名单设置。core 路径、自动启动/
接管意图、系统授权、插件权限、托管材料、来源正文和端点覆盖不在迁移范围。
未知字段、带凭据的 URL、可能含秘密的 DNS 材料拒绝导入；导出整块省略不满足
边界的 DNS，并在预览列出省略范围，不生成破损的部分 resolver。
迁移仅允许系统/IP 或现有内置公开 DNS 解析器的精确主机名，TLS 名称同样受约束。
测速 URL 仅允许根路径和当前内置公共测试路径。自定义上游及特殊路径仍保留在
原设置和完整编辑器；此限制只用于迁移，避免把可能携带访问标识的字符串当作
无敏感材料导出。原生 decode/encode 后逐层核对输入字段，补足原生 unit variant
忽略多余字段的边界，不复制一套 matcher schema。

输入最多 2 MiB。现有局部参数、IP/CIDR、地址族、MTU、端口和 DNS 全引用验证
与原生 Zero parser 共同检查材料。没有当前普通来源配置时明确保留兼容性待预检，
不会把语法合法当作当前手机已编译协议或平台支持的证明。

## 预览、发布及未知结果

只读预览固定允许覆盖的字段、完整 AppConfig 指纹、ClientScope、来源更新时间
和五分钟有效期。提交必须来自宿主主窗口并通过现有管理准入，在配置操作锁下
再次校验。`compare_and_replace_local` 持设置锁完成完整 typed CAS、原子存盘和
内存发布，存储失败保留旧设置；不删除源或其他领域的偏好。

提交仅保存本地材料。网络设置变化显示“待应用”，由配置工作区另行预检和应用；
主题等纯应用偏好不会错误地宣称等待内核。不会自动启动 VPN、重启内核或回滚
某个未确认的运行提交。命令状态读取也取得配置操作锁，避免在队列中或执行中
把原保存错误地当作未提交。缺回执时界面保存原 plan，只核对原操作，不自动
重复导入；进程重建丢失内存 plan 时需要重新核对本地设置，不声称恢复原回执。

导出预览返回当前设置指纹，系统导出在准备宿主 payload 前再次比较。原生 IO
只接收宿主序列化出的内容，界面不能向此命令传任意正文或系统路径。
系统分享已接受与接收方保存分开，取消保留草稿及导出预览。

## 验证与限制

包含原子存储失败、完整 CAS、owner/期限、来源版本、秘密排除、完整 DNS 引用、
地址族、Fake-IP 冲突、未知回执不重放和晚到结果的 Rust/客户端回归。
浏览器验证使用真实组件及明确的替代 IO，不代表手机系统文件验收。
[原生文档边界](native-documents-v0.0.3.md) 分别记录实际 Android 库、Swift
策略构建和仍需设备测试的项目。移动 VPN/core 桥尚缺失；这里的本地保存不能
据此被称为手机运行配置已生效。
