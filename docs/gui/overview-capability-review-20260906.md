# 专业概览能力组织校正

日期：2026-09-06。状态：确认稿已接入客户端源码，发布另行执行。

## 产品边界

用户要求保留旧版专业客户端的交互、信息密度、展示风格及应用标识，参考 Surge 的能力组织，解决功能重复。此前独立网页预览擅自替换了窗口、导航与 Logo，不作为产品方案，已撤下。

基准：`1f3f6d6` 的 `OverviewTab.svelte`；当前 RC：`6b734d4`。标题栏、导航、主题、Logo、简约/专业切换、托盘和窗口行为沿用现有实现。浏览器用于承载真实组件的对照，不另建网页产品外壳。

## Surge 参考及适用范围

官方排错指南先区分请求是否出现在请求查看器：没有请求时检查系统代理/增强模式接管；有请求时查看该请求的转发失败原因。适合借鉴的是“概览接管状态 → 具体连接 → 原因/修复入口”的连续操作过程。

官方策略组文档将规则引用与具体代理选择分离，手动选择、自动测速属于策略组职责。Zero 已有 selector/urltest 和相关界面，应清晰呈现自身真实支持的能力。此核查不承诺复制 Surge 的 Smart、MITM、重写、脚本等其他产品能力。

来源：

- https://kb.nssurge.com/surge-knowledge-base/guidelines/troubleshooting
- https://manual.nssurge.com/policy-groups/overview.html

## 实施原则

1. 用真实组件恢复旧版概览的交互基线，保留已修复的状态过期、失败反馈和流量真实性保护。
2. 清理同一页面内重复的速率/模式/状态显示；保留跨页面全局操作，不因去重移走日常开关。
3. 以接管故障、节点故障、DNS 故障三个任务核查页面衔接，并补齐带上下文跳转。
4. 在 900×650、窄窗口及深浅主题中验收，并验证失败时仍可关闭接管、模式切换不重置同一接管会话。

完整连接筛选跳转与域名诊断上下文联动仍属后续工作；本次实现已确认的概览设计与现有命令接入。浏览器模拟不能替代原生端到端网络验收。

## 设计确认阶段的优化预览

新增 `tests/client-preview/OptimizedOverview.svelte`，默认展示优化版，底部可对照原版与当前 RC。保留真实应用外壳及核心控件；概览内将重复状态栏改为活动配置操作，独立版本卡改为摘要入口，网络与自测合为一行；策略失败可直接切换对应组，TUN 异常可查看原因并独立关闭。

预览内已验证配置切换、策略故障处理、TUN 独立关闭与窗口布局。当时操作仅为模拟数据。现有命令接线已在下述正式实现中完成；完整连接筛选跳转仍未增加。

## 已认可布局上的细化

- 策略卡直接显示组名、已选节点和近期探测延迟；探测失败、过期及直连模式分别标注，避免将某个策略组误称为所有流量的实际出口。
- TUN 卡保留原有卡片样式与 Switch，突出接管开关和健康状态；地址、MTU、出口接口、网络代次等参数集中到接管详情。开启但不健康时显示“已开启 · 异常”，异常原因和处理入口仍在概览可见。
- 配置、模式、策略与接管切换均区分请求中和已确认状态。预览通过 Svelte 函数绑定保持内核确认值，失败不提前改变选择，并在操作位置显示错误。成功反馈短暂显示后收起。
- 增加“切换失败”预览场景，供检查等待、失败保留原设置及再次操作。设计确认后，已通过现有命令与状态回读接入正式组件。失败路径在命令适配器替身与浏览器夹具中验证，未操作本机正在运行的内核。

## 正式实现

- `OverviewController.svelte` 连接真实 GUI 状态、配置列表与切换服务、内核模式/策略选择、TUN、系统代理及网络检测；`ProfessionalOverview.svelte` 保持确认稿的布局。
- `TunControl.svelte` 与 `OverviewDialogs.svelte` 提供接管开关、参数展开、就绪检查、策略选择和已有设置入口。自动选择组只读，selector 只能选择直接成员，包含嵌套组的标签。
- `OverviewOperations` 统一等待、错误与短暂成功反馈。命令服务返回可检查的结果；回读失败明确显示“已提交但未确认”，不会提前显示成功或编造回滚结果。
- 活动配置继续调用 `setActiveProxyConfig`，沿用 TUN 交接和事件重连。成功响应更新已确认配置；后续读取失败显示独立错误，不把已提交变更当成回滚。
- 保留流量新鲜度、状态过期、缺失自测与实际策略观测保护。增加策略快照时间/错误，连接状态新鲜并不掩盖策略读取失败。
- 简约模式沿用原页面，只在进入简约模式时读取其订阅来源；Logo、窗口与完整导航沿用现有实现。

浏览器入口仍为 `tests/client-preview/overview-preview.html`，现在默认加载正式页面与控制器，服务由该 Vite 配置替换为模拟适配器；可对照已确认设计稿。未修改 Tauri 后端或内核代码，本轮没有发布 RC 或替换正在运行的客户端。
