# 概览定位与移动运行网络

2026-10-15，基线 `90557080d337258f956dea68a22ba8323b43e43c`，沿用 Draft PR #46 → develop。
本文只说明 A04 客户端定位及 A12 有限网络编辑增量，不表示真实手机 VPN 或全部 A04/A12 已验收。

## 概览到实际对象

概览的当前配置入口按配置 ID 定位，当前出口按已确认模式解释：

- 规则模式显示按规则选择，不拿历史 `globalOutbound` 当作所有连接的唯一出口。
- 全局模式使用实际 NodeScreen 的组／节点身份、直接成员及运行选择链；缺失、循环、relay 顺序或未确认叶子保留原因。
- 直连是模式；没有声明节点时不制造一个 `direct` 资源。
- 离线、未知模式或缺失全局目标只显示出口未确认，可浏览当前配置目录，不降级标成规则模式。
- 没有活动配置时进入最新配置列表，不自动创建、启用或打开同名配置。

新增 `gui_mobile_location_snapshot` 是只读目录接口，只返回公开配置 ID／名称、opaque binding 及十进制字符串作用域。
binding 包含唯一宿主 session、完整客户端 scope/generation 和目录关系元数据；普通观测 revision 不使其失效。
不读取配置正文、外部路径或 SQLite，不查询内核，不授予控制／运行权限，也不证明来源文件或运行已经生效。
真实正文编辑仍由原 ProfileEditor 的宿主快照、准入和 CAS 负责。

概览先后核对目录身份，再使用真实列表／NodeScreen；点击时重新核对原身份及模式，不替换成最新同名对象。
目标页抵达、重新显示或执行已有动作前继续核对；配置、宿主、实例、generation 或目录变更后，原目标只作历史。
用户可明确选择浏览最新列表，重新开始普通浏览；不会自动恢复旧可执行选中对象。

跨底栏访问是一次 guarded `visit`，把新的实际配置／节点页放在目标底栏栈顶。
原目标底栏栈、根页面搜索和滚动继续保留，不清空旧工作区或订阅分段。
固定 origin 和导航代次；迟到草稿确认及读取不能在离开再返回后重新跳转。
返回优先关闭最上层面板；普通嵌套页先回定位页，再回精确来源。来源栈已经变化时保留最新页面并说明，不裁掉新草稿。
dirty、busy 和未知结果继续使用原编辑器保护；不会取消或重放在途操作。

定位只临时揭示固定组链或节点，不改用户的搜索、离线过滤、排序偏好和配置顺序。
列表定位限定在所属组件容器内，避免多个挂载底栏中的同名 DOM 命中隐藏页面。

## 移动运行网络的本地边界

移动／响应式布局使用新的 canonical editor；桌面继续原设置页面。
新增五个接口：`gui_runtime_network_snapshot/preview/save/status/discard`。
前端提交窄字段和原 binding，确认后仅提交原 plan ID；不将完整配置 JSON 经 JavaScript 往返。

| 字段 | 本批范围 |
| --- | --- |
| MTU | 同一 `tun.mtu` 全局覆盖，整数 576–65535；客户端显式覆盖 > 来源 `runtime.tun.mtu` > 来源 `runtime.network.mtu` > 1500 |
| UDP 上游空闲时间 | 正 u64 十进制字符串，保存为原生整数，不转为不安全的 JavaScript number |
| 本地监听 | 只修改来源已经声明的第一个 mixed/http/socks5 监听的地址／端口；literal IP、端口 1–65535，不新建监听器 |
| LAN 范围 | 从监听 IP 派生；回环、全部对应地址族接口和指定地址分别显示，非回环在固定预览中说明影响 |
| 地址族／物理出口 | 只读来源中每个 Direct leaf 的 `dial.address_family/interface/source_ip`，给出工作区入口；不冒充 DNS 地址族、TUN 双栈或系统网络控制 |

移动 TUN 页不再维护第二个可编辑 MTU，只显示同一 canonical 最终值并跳到运行网络。
576 是固定 core schema 的下限；实际平台接口、IPv6、地址归属和绑定仍需运行验收，不由表单范围保证。
空或缺失 inbounds 不增加默认监听；配置地址不代表设备实际拥有该地址或已经对 LAN 开放。

来源仅限普通内嵌 Zero 材料。托管、受保护、path-only、损坏 schema 或不一致活动身份拒绝投影正文。
来源的规则集／GeoIP 路径不在此页打开；只做 typed schema 投影，不调用会编译外部依赖的 runtime parse。
未规范化的旧全局覆盖保留并说明，不能借修改一个网络字段偷偷迁移其他旧设置。

## 固定提交和未知结果

预览固定 profile、源摘要、完整关系图、AppConfig／规则文件历史、持久关系 epoch、宿主 session 和 scope/generation。
只发布四字段白名单中的修改／恢复；来源、规则、订阅、SQLite 关系和其他偏好保持原值。
恢复只删除明确确认的覆盖 key，不删除来源或顺带恢复其他字段。
本地发布使用原 owned file receipt 与后置状态核对；同值 ABA、后来写入者和旧宿主不能补造原成功回执。
保存结果为 `saved_pending_apply`，不调用 IPC、进程重启、TUN、监听或系统代理重定位。
全局覆盖影响其他配置的意图会说明，不保证其他保护来源及设备的运行兼容性。

每个宿主最多四份预览、五分钟期限；未知结果保留原 plan 并阻止替代提交，不回滚、不重放。
前端核对原 status 后还需 fresh snapshot 与原成功回执一致；相同当前值不能代替原回执。
原操作只在当前宿主内存持有，不声称跨进程持久恢复。

重新显示页面或恢复前台只读核对来源；相同binding/版本/值保留可继续编辑的草稿，变化后旧草稿只读。
明确的放弃确认后才重读新来源；读取失败保留输入并禁编辑/预览，unknown或busy不被刷新替换。
