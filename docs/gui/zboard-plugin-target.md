# ZBoard 联动插件：主线场景与权限设计

2026-09-12 后续架构纠正：以 [客户端统一入口、管理与执行管道](./unified-capability-plan.md) 为最新实施方案。插件业务由插件实现，所有内核操作经客户端代理；普通与受保护来源共用一条执行链。本文旧业务权限名、插件直连/解密所有权和独立执行路径仅作历史候选，冲突时以上述方案为准。

2026-09-12，根据用户最新场景固定目标。**本文为后续实现的主线验收契约，不表示这些业务能力已实现。** 已有代码仅覆盖插件分发安装、有限 VM 和两项只读能力。本文优先于旧候选中独立 worker 前置、仅配置下发及暂不实施插件的描述。

## 用户使用流程

1. 安装 ZBoard 联动插件，在 ZNet Sink 内添加一个面板源：名称与 HTTPS origin。一个插件可绑定多个源，各自独立授权。
2. 插件申请连接该源和登录权限，ZNet Sink 显示来源、用途、权限范围。用户同意后使用账号登录或浏览器中的第三方登录。账号身份与回调由客户端验证，插件使用绑定账号的凭据句柄完成快捷登录。
3. 用户独立决定是否允许读取公告、账号通知，以及向客户端发布提醒。公告正文视为不可信内容；通知权限不附带账号秘密或订阅访问权限。
4. 登录后，用户选择有权访问的订阅并允许受保护订阅获取与密文缓存。插件通过绑定源的专用受保护会话获取密文；不生成普通订阅 URL 或普通配置正文。
5. 本地仅保存密文与安全元数据。可用设备凭据设施对接收的密文再封装一层本地加密，外层缓存密钥与面板配置解密密钥分开；没有适用设施的平台不启用持久缓存，不能退回明文文件。
6. 用户授权“用于连接”并发起连接后，敏感执行组件取得短期配置解密材料，在受限执行域内解密并直接提交到内核的内存配置事务。客户端界面只接收安全状态、别名、用量和应用回执。
7. 续期、断网、账号切换、退出、撤权、插件停用及内核重启都按同一生命周期处理，不绕过权限或回退到普通订阅流程。

快捷登录可以记住安全保存的可撤销续期凭据，不能等同于自动同意所有插件权限。第三方登录应复用目标 ZBoard 的既有登录能力；实施前核对现有提供者与回调契约，不预先创建平行 OAuth 系统。

## 业务权限由 ZNet Sink 定义并执行

插件只声明用途与申请范围。ZNet Sink 校验中心注册上限、组件声明和用户授权，并在每次实际调用时强制执行。以下是待实现的业务能力，不是系统权限列表；现有枚举尚未包含它们。

| 能力候选 | 用户授权含义 | 强制作用域 |
| --- | --- | --- |
| `sources.connect` | 连接所选 ZBoard 源 | 源实例、HTTPS origin、允许的操作模板 |
| `accounts.authenticate` | 登录并保持该源的账号状态 | 源、账号、登录方式、合法回调 |
| `credentials.use` | 使用该账号的登录状态 | 绑定账号与操作；不提供通用 token 读取 |
| `announcements.read` | 读取该源的公告 | 源与公开响应投影 |
| `notifications.read` | 读取该账号的通知 | 源与账号；与公告分开 |
| `notifications.publish` | 在 ZNet Sink 中显示该插件的提醒 | 插件/组件、来源标记、频率与内容限制 |
| `subscriptions.protected.fetch` | 获取选定订阅的受保护数据 | 源、账号、订阅、会话与版本 |
| `storage.protected.cache` | 在本设备保存该订阅的加密缓存 | 插件/组件、源、账号、订阅、设备 |
| `runtime.protected.load` | 将该订阅用于本机连接 | 上述绑定、运行实例、配置版本、操作租约 |

用户界面可按“登录该源”“公告与提醒”“受保护订阅”“用于连接”组织易懂的授权组，仍展示组内权限和具体范围。拒绝通知不影响已同意的登录；同意拉取不自动同意连接或自动启动。系统通知许可是客户端后续对接平台时的另一层检查，不代替插件通知授权。

同一插件不同源、不同账号之间不共享授权。更换源、切换账号或扩大域名/数据/操作范围必须重新核对，必要时再次询问；插件升级不能静默增加权限。撤权应使当前调用、后续调用及晚到结果失效，而不依赖插件配合。

## 两类组件分开授权

普通组件负责源设置、登录入口、公告与通知展示；敏感组件负责受保护订阅获取、秘密材料使用和内存应用。两者使用独立 VM、授权实例和数据空间，由 ZNet Sink 统一管理，不要求插件自建进程。

敏感组件不能同时拥有自由通知正文、日志、剪贴板、明文 KV 或任意 HTTP 输出权限。其输出仅允许受控阶段、错误码、操作 ID、版本和经过允许列表的展示数据。普通组件只能获得经过客户端约束的安全视图，不能接收敏感组件任意返回的字符串。

常规第三方插件不能仅靠声明并弹出一个“允许”就获得受保护解密角色。该角色须经客户端准入、可信发布者审查与专门 SDK 支持；用户授权是必要条件，不替代角色准入。有明文权限的恶意代码可以尝试通过合法输出编码泄漏数据，VM 本身无法证明其不会泄漏。

HTTP 不是不受限制的 fetch：使用绑定源、账号和业务操作的接口模板，约束方法、路径、重定向、凭据附加和响应去向。账号密码、通用 token、配置密钥不交给普通组件。OAuth 回调必须绑定发起会话、来源与账号流程，防止其他插件接管回调；具体 state/PKCE 等使用条件以实际服务端契约核对后实现。

## 受保护数据路径

传输采用 HTTPS，并沿用受保护配置契约中的标准认证加密与来源签名。所谓混淆只可作为附加表示，不承担保密、完整性或鉴权职责；不在插件中硬编码共享解密密钥，不自行发明密码算法。

```text
用户授权的 ZBoard 源与账号
  → 受限会话、加密且签名的配置信封
  → 敏感执行域校验来源/作用域/版本
  → 本地缓存：密文信封 + 可选设备加密外层
  → 连接时在线获取短期配置密钥
  → 敏感执行域内解密 / 受保护缓冲区
  → 内核 runtime-only 应用及 revision 确认
  → UI 仅接收安全回执与允许的展示字段
```

密钥所有权保持：ZBoard 管理配置加密密钥，面板主密钥不下发；配置内容密钥只在授权敏感执行域短时使用，不落盘。客户端账号服务持有自己的登录/续期凭据；设备缓存服务只能解开本地外层、取得仍加密的信封，不因此取得配置内容密钥。

首期默认在线取钥，不支持长期离线解锁。重启后可恢复源、账号绑定与密文缓存，但必须重新建立合法会话/租约；不能从明文启动 JSON 恢复。离线使用、自动连接和租约期限属于后续明确的产品策略，不由插件自行无限延长。

“宿主不接收配置明文”指 UI、账号、存储、日志及通用业务编排不接收正文，敏感执行域及其专用 SDK 是独立代码边界。同进程下不能声称宿主进程内存完全没有明文，也不能通过普通 JS 字符串/GC 保证所有副本清零。秘密缓冲区与直接内存应用通道需要专门实现和验证。

## 与普通订阅的边界

普通订阅继续使用已有导入、编辑、导出能力。受保护来源使用独立类型，只公开源绑定、版本、密文摘要、租约和安全展示字段；不能把正文写进普通 profile content 再隐藏 UI。

必须覆盖缓存、数据库/WAL、临时文件、启动文件、备份、错误、HTTP/IPC 调试、日志、诊断导出、剪贴板及内核查询/事件。拒绝敏感信息后端读取，不能只禁用按钮。插件不应获得原始内核 IPC 或任意配置写入口来绕过这些检查。

ZBoard 也必须关闭 protected-only 订阅的等价明文旁路，包括普通链接、其他格式导出和能恢复凭据的账号接口。否则用户仍可绕开插件获取相同配置。普通订阅策略保持独立。

内核“支持内存应用”只解决加载方式，不能证明后续不会导出或泄露。现有内核接口、观测输出和生命周期是否满足目标，实施前逐项核对；不足的通用能力单列契约需求，不悄悄修改 Zero，不用客户端隐藏来冒充内核保护。

## 生命周期与失败策略

- 源/账号切换：旧授权代次失效，旧响应不能写入新账号状态或驱动新连接。
- 用户拒绝或撤销某项权限：停止对应能力和任务，保留其他仍被允许的功能；撤销连接权限时由客户端清理该受保护连接。
- 登出、停用、卸载：撤销句柄和任务，清理会话秘密与该来源的运行状态；不依赖插件清理回调成功，不影响无关连接。
- 拉取/解密失败：不走普通订阅或明文落盘补救；旧配置仅在既定有效租约内按策略继续运行。
- 内核应用结果不确定：查询同一运行实例的操作回执，不盲目重放，不提前显示成功。
- 进程退出或内核重启：重新授权/取钥并恢复内存状态；不会自动复用旧秘密或重复有副作用操作。
- 公告/通知轮询由客户端有界调度，受后台和频率预算约束；插件不能创建无法回收的常驻线程。

## 落地顺序与验收

1. 固定 ZNet Sink 业务能力目录与通用授权界面，统一插件实例、授权代次、源和账号绑定；以本场景检验范围是否足够细。
2. 接通一个 ZBoard 源的账号/第三方登录、快捷登录、公告通知，以及相互独立的用户授权。先复用并核对服务端已有接口。
3. 客户端与 ZBoard 联调受保护会话、标准加密信封、密文缓存和在线取钥，覆盖篡改、重放、过期、串源/串账号与撤销。
4. 核对并接通内核内存事务和敏感出口限制，验证整个运行生命周期。缺必要契约的内核或平台显示不可用，不降级保护。
5. 在每个支持端分别验收，复用同一业务契约；独立进程/OS 沙箱为后续按风险增强项，不是当前第一步的前置条件。

验收必须用带唯一标记的测试配置完整走登录、缓存、连接、刷新、撤权、失败、重启及导出流程，检查全部应用可控出口不出现配置正文、密钥或可恢复凭据；检查公告组件、其他插件和未授权调用无法取得保护数据。加解密单元测试、安装成功、一次内存 reload 或隐藏编辑按钮均不代表整套目标完成。

“用户不可读不可见”的可交付范围是正常客户端入口和应用可控持久化/导出路径不暴露配置；不承诺抵抗本机管理员、修改程序或内存调试。内核运行连接时必然使用必要明文，同进程 VM 也不能隔离 JS 引擎原生漏洞或进程崩溃。
