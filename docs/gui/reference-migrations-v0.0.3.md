# 规则集引用与 DNS 删除/重命名迁移

本批延续 `64d1f53` 的普通配置路由规则编辑，在同一 Draft PR 中补充固定引用预览与本地迁移。
它不表示完整 A10/A13、原生 VPN 或设备验收完成。保存结果统一为 `saved_pending_apply`；
用户另行进入配置工作区预检与应用，运行成功仍需实际回执。

## 规则集身份、引用及范围

规则集记录的 GUI ID 与原生 tag 不同。公共资源的 tag 使用现有 `gui-common-<hash(id)>`
映射；名称、同名 tag 或相同 artifact 路径不能授予删除资格。替代必须是已有普通 GUI
资源，且启用状态、公共绑定、声明产物、当前模式与实际组合允许其定义出现。
迁移不搬动替代资源自己的 action 或 order；删除旧资源会移除旧资源的公共绑定，预览单独说明。
确认时只读取该资源原声明、私有 `rule-artifacts/<id>` 代次中的有界普通文件，核对完整 ZRS
及声明元资料，并以实际内容摘要绑定预览与提交；其他目录、符号链接/重解析点、FIFO、损坏或漂移均拒绝。
路径本身不授予资源权限，也不声称替代资源实际转发可达。
产物代次继续保留，已有运行实例可能仍映射这些文件。

宿主检查来源的 `route.rules`、`route.bypass`、`runtime.dns.dispatch` 的原生条件树，
全部 `routeRules` 覆盖行（包括停用行），以及客户端/保留的 DNS 覆盖。
递归采用实际原生 `and/or.items` 和 `rule_set.tag`；不把任意同名字符串当作引用。
UI 列出引用所在配置、字段路径、类型和原 tag，替代选择初始为空。

本版允许当前普通配置的引用迁移。其他配置实际引用、全局 DNS 引用影响多份配置、
孤立覆盖、托管/受保护/路径材料无法检查、来源与生成 tag 冲突等情况明确阻止整个候选。
托管材料先做归属检查，不把其正文或秘密放入普通 DTO。不会静默遗漏受限范围后继续删除。
内置资源和订阅托管资源沿来源管理边界，不由此入口删除。

来源正文及 SQLite 关系不改写。当前来源的引用迁移保存在
`AppConfig.profileEdits[profileId].ruleSetReferences`：版本、完整来源摘要和精确 tag 映射。
组合在 `routeRules` 之后、公共资源注入之前消费同一纯投影；DNS 预览也沿该链，不能重复投影。
来源变化使旧摘要失效，须明确重新处理覆盖，不能自动重绑定。
工作区只对带合法原迁移覆盖且 Value 完全未变的来源延后原文依赖解析：先检查原始文本 typed
schema/重复字段，组合后仍调用实际 native parser 完整验证。改变的来源不能借此读取新依赖。
原 JSON 值保留，u64 与未知合法字段不经 JavaScript number 往返。
结构检查不调用会读取依赖文件的 native parse/validate，不声称完成产物编译或运行可用性检查。

## 规则集本地提交与不确定结果

`gui_rule_migration_snapshot/preview/save/status/discard` 由宿主主窗口及当前客户端准入控制。
预览固定原配置、资源、替代项、引用集合和候选；确认只提交原 `planId`。
绑定包含来源、完整关系图及持久 epoch、AppConfig/规则集内容及文件历史、宿主会话和 scope 代次。
提交在既有配置操作锁、文件历史 guard、scope fence 与 SQLite 关系 fence 下重新核对。

两份文件没有天然原子提交：先保存全部受支持引用到 AppConfig，再删除旧规则集记录。
替代资源在开始时已存在，每个已发布前缀都保留可解释的材料。
若第一阶段成功、第二阶段失败，已经保存的引用不会盲目回滚，旧资源可能仍在。
阶段事实与原 owned write receipt 分开记录；最终成功还必须匹配两份原回执及严格后置状态。
后继 writer、同值写回、同 ID 重建或当前文件缺少资源都不能冒充原操作成功。

超时、断联或提交后不能确认时进入 `submitted_unknown`，原计划只读核对，不换 ID 重放、
补发删除或推断已回滚。计划为五分钟、最多四项的宿主会话内材料；未知记录保留屏障。
这不是跨进程迁移执行日志，重建进程不凭文件值恢复旧请求成功或可执行授权。
旧 `rule_set_remove` 快捷命令拒绝绕过专用预览，也不再先删除再自动协调运行态。

## DNS 服务器删除

新 `gui_dns_migration_snapshot/preview/save/status/discard` 从宿主持久材料选择服务器，
不接收页面重序列化的整份 DNS 候选。服务器及替代项均须明确选择，不按旧列表行自动授权新同名对象。
预览覆盖默认服务器、全部 dispatch、节点/直连解析、三个独立有序回退链和独立超时映射键。
`detour` 是出站标签，bootstrap 是地址，均不作服务器名称全局替换。

重复回退、主备冲突、超时键碰撞、最后一个服务器、失效目标、不能解释的扩展引用都拒绝，
保留原文与草稿；不会隐式去重、吞掉超时值或把默认服务器改成第一项。
即使 DNS 禁用，也检查保留配置的全部已知引用。
实际 ClientDnsConfig 结构/引用及原生 typed schema 校验不读取规则集或 GeoIP 文件；
该校验不证明依赖已编译、物理出口或平台 DNS/TUN 生效。

保存的是全局客户端 DNS 覆盖，预览明确影响所有配置；来源正文不变。
其他托管/受保护配置的兼容性与实际运行不在此保存回执中得到证明。
CAS、文件历史、关系 fence、会话/代次和 owned receipt 核对沿本地保存契约，
未知操作阻止同域新计划及旧快捷入口重放。
旧快捷保存若删除或重命名已有服务器，会在任何运行/落盘效果前拒绝；普通新增、参数编辑保留。
专用重命名流程见下节；普通编辑器仍不接受未经预览的名称变更，保留草稿并引导独立入口。

DNS 面板有未保存修改时先保留并提示继续编辑或明确放弃重读，不用宿主快照覆盖脏稿。
提交期间阻止返回、Escape 和重复提交。成功后重读当前材料；读取失败则禁用旧表单保存。
只读核对也须重新核对当前配置和原成功 binding，不能采用晚到或后继写入的成功回执。

## DNS 服务器重命名（2026-10-16）

同一组 `gui_dns_migration_*` 命令新增窄意图 `renameTo`。省略或 `null` 保持原删除语义；
非空重命名必须同时令 `replacementName=null`，不能借此合并另一服务器或删除后新建。
UI 从本次宿主快照重新明确选择服务器并输入新名称，不把原列表同名行自动当作授权。
预览固定原名称、新名称、配置/binding、全部引用与 Rust 候选；确认仅提交原 `planId`。
DTO 没有 DNS 正文，u64 不经 JavaScript number 或 JSON 往返。

Rust 移动原服务器定义的完整 Value，只迁移默认解析、dispatch.server、节点/直连解析、
三个独立有序回退链及独立超时键。顺序、超时值、未呈现的有效原生字段和服务器参数保留；
host、域名条件、bootstrap、TLS 名称与 detour 都不是 DNS 服务器名引用，不作字符串替换。
允许仅有一个服务器时改名。新名须不同、未占用、1–512 UTF-8 字节，无首尾空白或控制字符；
超时键碰撞、原配置悬空引用、重复/主备冲突和同名不明扩展明确拒绝，不借重命名修复或吞掉冲突。
先校验原对象，再核完整候选与预算；原生 schema 不接受的字段保留在原材料并拒绝，不能删字段造成功。
DNS 禁用时仍检查保留对象的全部引用。

已有持久 `clientEdits.dns` 或实际被采用的旧全局 `overrides.dns` 是同一封闭全局对象，可在上述范围保存，
包括保留的禁用配置。其它配置、托管关系与来源正文不改写，也不读取其它受限来源来扩大证明。
没有显式全局 DNS 时，单份普通可读来源可沿已有契约晋升为全局覆盖；若存在多份配置，或当前
来源已有 `ruleSetReferences` 投影元资料，则返回 `dns_migration_scope`，零写入并保留原文。
后者避免原始 DNS 覆盖已迁移的规则集标签。派生的旧 profile DNS 不算已持久全局授权；
混合旧格式中即使有全局标记，若实际优先采用 profile DNS，也仍按来源晋升限制处理。
跨配置/托管来源重命名与带来源投影的晋升仍待适配，不能静默回写来源或声称其它配置已兼容。

保存沿原 AppConfig 本地 CAS、文件历史、图 epoch、host/scope 代次及 owned receipt；只得到
`saved_pending_apply`，运行 DNS、平台 DNS 与 VPN 尚未应用。此操作不改 SQLite 来源关系，
不构造跨文件原子事务。过期预览、后继写入与 A→B→A 均不能复用原许可。
提交期间锁住重复动作与返回。缺回执时保留原 `planId`，只读原 `status` 证据；若原操作实际已有
成功回执，还需核对当前 snapshot binding 才能显示本地已保存。未知不换 ID、不重放、不补写或盲目回滚。
进程内计划仍有五分钟/四项预算；未知记录保留屏障，未提供跨宿主重建或进程恢复保证。

## 验证与平台边界

后端测试使用实际 AppConfig、规则集文件和 SQLite 重开，验证原关系保留、无损 u64、
文件/关系 ABA、目标失效、分阶段故障、未知不重放及后继 writer 不冒充原回执。
前端测试覆盖真实移动壳入口、320px 触控、明确选择、全部引用、草稿与返回保护、固定预览和晚回执。
准确本地结果和最终 SHA 的 Chromium/WebKit CI 见[统一验证记录](../verification/mobile-client-v0.0.3.md)
与原 Draft PR。浏览器、未签名包和对象编译不能替代 Android/iOS VPN 与真机验收。
