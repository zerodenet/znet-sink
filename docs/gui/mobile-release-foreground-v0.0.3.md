## 已保存策略与实际执行

现有 `releasePreferences.clientAutoCheck` 是唯一客户端自动检查开关，使用已保存的
`clientChannel`；编辑中的渠道、kernelChannel 及历史页面均不授予自动检查权限。
内核目录仍由用户明确检查，默认随应用维护内核；不增加自动内核安装或下载代码权限。
桌面 updater 的既有定时及安装路径保持独立，响应式移动预览不冒充原生移动生命周期。

移动主窗口 Ready/Resumed 唤醒 Rust 宿主 owner，主窗口 Suspended/退出撤销前台代次。
owner 仅持有一个前台 worker，按到期时间及策略变化唤醒；连续保持前台跨到期点也检查，
不依赖版本页、WebView 定时器或页面是否挂载。成功后六小时、失败后十五分钟重试窗口；
错过多个窗口合并为一次当前检查，不补发历次任务。后台不发起新检查，已发 HTTP 不声称撤回。
OS 后台调度、锁屏准时执行和进程外常驻均仍未适配。

原有已保存开启策略从可信本地状态读取；损坏 checkpoint、CAS 冲突或未确认偏好写暂停自动执行，
不能默默重置记录。关闭自动检查仍允许用户显式读取目录。页面显示最近实际尝试/成功、到期或
重试、进行中、旧缓存和阻断原因；没有真实结果时不显示“已是最新”。

## 真实目录与请求归属

自动与手动目录读取共用宿主 single-flight。固定源为 `zerodenet/znet-sink` 和 `zerodenet/core`，
固定 GitHub HTTPS API；共享网络/下载 executor 负责时间与字节预算，不接受网页提供的 URL、
下载路径或身份。每次响应最多 4 MiB、30 条发行记录、30 秒；不跟随重定向离开允许来源。
发行说明按原预算以纯文本显示，缺失、超限截断和无当前版本的比较分别表达。

只在真实 200 完成结构验证后发布目录及对应 validator；304 必须有同源的已验证原正文和实际
发送的有效 validator，才可复用，不能把空正文、无缓存或读取失败当作权威空目录。
缓存正文仅在当前宿主会话内有界持有；进程恢复后没有正文便不发送条件头，下一次实际检查重新读取。
持久 checkpoint 上限 64 KiB，只存有限时间、结果及最多八份偏好操作记录；审阅绑定五分钟有效。
复用独立的共同存储命名空间，不存完整说明。

请求固定 source、channel、宿主与客户端作用域/配置代次。变更策略、切换配置、实例变化、
后台及宿主重建后，旧结果不能确认新渠道/新代次的检查时间或覆盖当前页面；仍有效的旧目录附时间。
普通 GET 中断可在后续合法窗口重新读取，不套用有副作用订阅写的永久 UNKNOWN 状态。

## 偏好保存与未知结果

保存前固定客户端生成的 operation ID、原设置版本和确认的偏好。宿主持久登记原意图，
复用 owned AppConfig 文件历史与发布回执；仅更改发行偏好，不修改配置正文、订阅、规则或运行态。
新偏好收到原保存回执并确认该原操作后才成为可执行自动检查授权；确认仅更新调度授权元数据。

保存/确认回复缺失时保留原 ID；只读查询原操作及真实回执，不再调用 save 或以新 ID 重投。
当前值相同不能补造原回执，目录请求成功也不解除偏好写屏障。明确审阅后的确认重新核对原
候选与文件历史；后来写入者、同值 ABA 和失效身份要求重新审阅。检查原操作不修改任何业务资源。

A09 已有来源同步继续自己的下载/304、材料验证、运行回执和 UNKNOWN 屏障；本批不读写或清除它们。
目录发现新版本只代表公开项目资料，不触发应用安装、内核替换、配置应用或系统授权。
