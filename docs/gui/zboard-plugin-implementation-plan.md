# ZBoard 双端插件落地计划

日期：2026-09-15。目标版本：v0.0.1。状态：方案修订，待实施。

## 1. 产品定位与本次边界

GUI 插件负责配置 ZBoard 源、账号密码授权、读取有效订阅、将选定订阅关联到客户端，以及该源公告/站内信的通知与只读展示。它不是 ZBoard 的另一个面板，不承接套餐中心、购买、消息编辑发送、账号管理或设备管理页面。

同一项功能以双端插件交付：客户端安装 GUI 插件，ZBoard 安装配套服务端插件。两端均启用且服务端开启客户端通信后才可使用。服务端插件拥有专用加密通信协议、设备授权记录和嵌入式用户/管理员页面。

核心业务数据方向固定为：

```text
GUI 插件 → 客户端订阅 → 客户端配置
```

传输方向固定为：

```text
GUI 插件
  → 客户端受控网络能力（按设置直连或经过内核）
  → ZBoard 服务端插件专用通信入口
  → ZBoard 宿主内部授权能力
```

客户端交互顺序固定为：

```text
添加 ZBoard 服务地址和通信路径
  → GUI 插件发现远端 Connect 插件并自动建立服务身份/设备密钥绑定
  → 插件页面临时收集账号和密码并完成设备授权
  → 拉取当前账号有权使用的订阅列表
  → 用户选择订阅
  → 插件拉取订阅详情并创建或复用客户端托管来源关联
  → 客户端既有订阅同步、配置生成与运行流程
```

服务端密钥、公钥指纹、账号和密码都不是普通来源配置字段。密钥由双端插件在受控交互中生成、协商和持有；账号密码只在需要首次授权或重新授权时由插件页面临时取得。客户端宿主只提供通用秘密、密码学、网络和来源能力，不替插件制作 ZBoard 登录表单或保存业务凭据。

v0.0.1 完成上述双端基础、设备授权、自动续期登录、清空授权、通信加密、统一订阅同步及通知阅读。一个仓库产出两个宿主安装包，在统一市场注册一个插件产品，声明 ZBoard 与 ZNet Sink 两个适用目标。本地配置加密、不可导出及受保护内存材料在后续版本实现，不作为首期完成条件，也不能提前宣称已具备。

本文沿用 [统一能力方案](./unified-capability-plan.md) 的执行边界；在 ZBoard 业务范围、双端结构与版本顺序上，以本文为准，取代本文件前版以及 [旧业务目标](./zboard-plugin-target.md)、[旧保护设计](./protected-config.md) 中的冲突安排。首期不接 OAuth，不调用 ZBoard 原生公开登录、订阅 API，不以那些 API 的 token 规则规定本插件会话。

## 2. v0.0.1 功能清单

### GUI 插件

- 添加、修改、移除 ZBoard 源；普通源设置只包含名称、HTTPS origin 和通信方式。可信服务身份与设备密钥由插件在远端交互中自动建立，不要求用户填写公钥或指纹。
- 通过专用加密协议完成账号密码授权、设备登记及有效订阅查询。
- 选择订阅后，在客户端既有订阅菜单中创建或关联一条插件托管订阅。
- 经客户端调度周期核对源、授权及订阅变化，调用同一订阅同步入口更新配置。
- 展示完成这些操作所需的源状态、登录状态、有效订阅选项和错误提示。
- 通过客户端通知能力提示该源的公告/站内信，点击“查看”由客户端跳到插件内对应的只读详情；不提供回复、发送或其他复杂业务操作。
- 经受控网络与秘密能力自动续期；服务端要求重新授权时停止续期并提示密码登录。

### ZBoard 服务端插件

- 插件启停与“允许客户端通信”分别控制；通信默认关闭。
- 在首次双端交互时使用密码学安全随机源生成或载入服务端通信身份，私钥留在服务端；协议自动返回完成可信绑定所需的公钥、key ID 和证明材料，不要求用户复制粘贴。
- 插件自己声明并处理专用路由，负责加密登录认证、设备授权、自动续期、清空授权、订阅列表/内容、消息列表/详情与同步协议。
- 一键清空本人、指定用户或全站客户端授权，按角色限制范围，要求相关客户端重新授权。
- 插件用户页面：本人授权设备、设备状态、上次登录时间和 IP，并可撤销本人设备。
- 插件管理员页面：用户设备数、设备明细、上次登录时间和 IP、撤销入口，以及通信开关和密钥管理。

### 客户端宿主

- 提供通用网络、秘密输入/存储、密码学、来源提供者、任务调度、订阅投递、通知与插件内部导航能力。
- 复用已有订阅关联配置、解析校验、周期更新、配置合成和运行功能。
- 负责来源不可被普通 URL 编辑接口替换、任务去重、撤权与晚到结果失效。

## 3. 责任边界与实际缺口

| 责任方 | 负责 | 禁止越界 |
| --- | --- | --- |
| GUI 插件 | 面板源和协议适配、授权/续期与选择业务、远端状态核对、通知内容与只读详情 | 自建配置列表/连接后台、直接写活动配置、自行创建网络栈或常驻线程 |
| 客户端 | IO 与秘密能力、订阅来源绑定、统一调度与订阅到配置执行、通知投递与安全导航 | 写死 ZBoard 业务协议、向插件开放原始 IPC 或任意内部命令 |
| 服务端插件 | 自有路由、登录与续期协议、设备授权/清空、订阅与消息获取编排、插件自有数据和页面 | 复制账号库、读取密码哈希、直写核心订阅/权益表 |
| ZBoard 宿主 | 密码验证、用户身份、权益判断、订阅内容生成、内部能力授权 | 将核心数据库句柄或管理员 token 交给插件 |
| Zero | 执行客户端选择的网络路径及既有配置 | 理解 ZBoard 登录、设备、会话或插件协议 |

“不依赖原生 API”指双端不调用 ZBoard 原生公开 HTTP 业务接口。服务端插件仍通过受限的内部 Host API 验证现有账号、读取有权订阅并请求已有渲染器生成内容。业务认证入口、路由、会话政策和协议响应属于插件；宿主提供受限基础操作，保留账号及权益的权威判断，不将整套插件业务搬入宿主。消息同样通过受限 Host API 取得当前用户有权阅读的公告/站内信，不复制 ZBoard 消息系统。

两端遵守同一扩展原则：插件声明路由、页面、任务和能力需求，由宿主框架注册、鉴权、预算和回收；缺少能力时补通用扩展点，不在宿主路由表或业务流程硬编码本插件分支。停用/卸载只移除本插件注册和资源，不改变 ZBoard 原生登录、订阅、消息及其他插件行为；GUI 插件停用也不改变普通订阅、其他来源及全局通知行为。

本地只读核对基线 GUI `8d9c99e`、ZBoard `8a42346`，非线上版本证明：

- GUI `src-tauri/src/models/subscription.rs` 当前有必填 `url`、`target_proxy_config_id`、周期同步字段；必须扩展来源类型，不能用伪 URL 假装已经支持插件来源。
- 客户端 [迁移记录](./capability-migration.md) 记载了签名包、受限 VM、受控网络和普通配置应用基础；秘密能力及完整插件订阅桥不能据此视为完成。
- ZBoard 插件 manifest 有 account/admin 页面声明，现有 PluginControl 有身份提供者和配置相关 RPC；这些不等于已提供本方案需要的密码验证、订阅生成或专用通信入口。
- 阶段 0 必须核对并补齐缺少的通用宿主能力。不能将旧原生登录接口直接包一层代理来替代内部受限能力，也不另开绕过宿主治理的服务端监听后台。

## 4. 订阅关联：引用来源，不复制下载链接

### 4.1 统一来源模型

客户端订阅来源使用明确类型，概念如下，正式命名沿用工程约定：

- 普通网络订阅：保留原有 URL 和编辑行为。
- 插件托管订阅：持有宿主管理的 source binding，绑定插件身份、源实例、账号授权、远端订阅 ID 和绑定版本。

订阅菜单展示名称、来源标识、同步时间/状态、周期设置及关联配置。面板源地址本身不是秘密；密码、会话凭据、设备私钥、可直接下载的 bearer URL 和完整协议响应不能作为菜单或订阅记录字段暴露。

凭据使用安全存储引用。绑定记录只能经受控来源操作创建/变更；普通订阅 upsert 不得将插件来源改成 URL、换账号或替换远端订阅 ID。用户可以取消关联，重新选择必须经过插件授权流程。

同一绑定重复选择幂等返回既有订阅；同步更新既有关联配置，不逐次创建副本。删除订阅复用现有配置关联与共享引用规则，不盲删仍被其他订阅使用的配置。

### 4.2 最小更新路径

```text
手动同步 / 客户端周期到期 / 插件周期核对发现变化
  → 同一个客户端订阅同步入口
  → 根据来源类型调用来源提供者
      普通 URL：既有网络来源
      插件来源：GUI 插件经客户端网络能力请求服务端插件
  → 核对授权、绑定、版本和完整性
  → 既有解析、校验、订阅元数据更新
  → 既有订阅关联配置更新
  → 按既有用户设置决定是否应用运行配置
```

来源获取可以不同；获取之后只有一条订阅到配置执行路线。插件不得直接跳过订阅层写配置，也不能因为刷新完成就改变用户的连接意图。

### 4.3 两种周期职责，共用调度和提交

- 客户端订阅周期：触发内容同步、关联配置更新。
- 插件周期核对：检查设备授权、远端订阅是否仍有效、源身份和版本变化；有变化或达到内容更新时间时请求同一同步入口。

插件定义业务核对动作，定时执行由客户端已有调度能力承载；没有配置页面打开也能被调度。两种触发按 source binding 去重，共用在途任务，不能双重下载和双重写配置。授权失效的核对优先阻断后续提交。

周期核对用于及时发现变化，不能替代每次请求和提交时的绑定检查。远端提供新地址不能直接写回普通 URL：优先专用协议按订阅 ID 获取；确需跳转时必须满足 origin 授权、公钥信任及显式源变更流程。

### 4.4 关联是否泄漏

关联本身可以仅保存不带秘密的引用，因此无需暴露订阅下载凭据。后端还需拒绝篡改绑定、跨插件/账号调用，以及将已校验响应投递到另一份订阅。

但是 v0.0.1 将内容交给现有配置能力之后，本地普通配置可能可读、可导出。通信加密与绑定保护不等于配置保密，也无法阻止修改客户端程序的人读取其已解密内容。后续本地保护阶段再覆盖这些出口。

## 5. 服务端密钥、设备身份与加密通信

### 5.1 密钥所有权与首次信任

- 添加源时，GUI 插件通过可信 HTTPS 发现远端 Connect 插件；远端插件生成或载入服务端通信身份，双方在专用协议握手中自动交换证明材料并建立来源、服务身份和设备身份的绑定。普通配置和客户端宿主页面不展示可编辑的公钥/指纹输入框。
- 服务端私钥只在服务端秘密存储，客户端只保存宿主安全存储中的设备身份和服务信任引用。页面可以只读展示连接状态、key ID、轮换状态或经验证的身份摘要用于诊断，但这些值不能由用户手工覆盖。
- 仅从未认证地址取得公钥再加密不能防止替换。首次绑定必须依赖 HTTPS 服务端认证以及冻结协议中的服务身份证明；若产品仍需要人工首次信任确认，应由插件页面展示握手得到的只读身份信息，而不是让用户填写指纹。
- 已绑定来源的公钥变化不得静默接受。正常轮换使用可验证的旧到新信任过渡；无法验证的替换进入明确的重新信任流程，失窃应急撤销与正常轮换分别处理。
- 通信开关关闭或服务端插件停用后拒绝新的客户端业务请求，并使会话失效；重新开启后重新建立合法会话。

### 5.2 设备身份不能只由服务端公钥生成

公钥公开，不能单独证明“这是同一台设备”。建议以客户端安全存储中的随机安装身份/设备密钥对作为设备身份基础，再结合源实例和可信公钥绑定形成该源的设备标识。对外称设备指纹，但不依赖 IP、MAC 或硬件序列号作为唯一证明。

首次密码验证通过后，客户端插件经宿主秘密能力生成或取得设备身份，提交加密的设备登记信息并证明持有设备私钥；登记绑定账号、源和服务端 key ID。公钥用于保护协商和登记数据，不是设备秘密的替代物。

- 密码输入与初次验证本身也必须在已认证的加密通道内，不能等设备登记完成才加密。
- 重启复用设备身份；重装或设备秘密丢失按新设备处理，不伪装成旧设备。
- 服务端正常密钥轮换不应重复累计设备；保持稳定设备记录并迁移其服务端密钥绑定。
- 不采集跨面板可关联的原始硬件指纹；客户端标识可被复制的风险不等于硬件可信证明。v0.0.1 不承诺阻止管理员复制设备秘密。

### 5.3 全部业务正文加密

HTTPS 保留；其上使用成熟密码学方案保护插件请求与响应业务正文。协商公钥、协议版本、key ID 和必要路由元数据允许公开，密码、设备登记、会话凭据、订阅查询和内容、业务错误详情均进入密文。

协议采用标准公钥封装/密钥协商和认证加密，不实现“公钥加密所有字节”或自创密码算法。HPKE 可作为公钥封装候选，具体 Rust/Go 库、套件和协议组合在阶段 0 核实后固定；HPKE 本身不是完整的设备认证、双向会话或防重放协议。[RFC 9180](https://www.rfc-editor.org/rfc/rfc9180.html)

必须明确双向独立密钥/随机数使用、请求 ID、会话与源/设备绑定、序号或防重放窗口、响应关联、超时、大小限制和协议降级拒绝。认证加密绑定操作和目标，不能将某订阅响应替换为另一订阅。凭据不放 URL，敏感错误不回显明文。

抓包验收目标是无法从业务报文直接读到上述内容；IP、时序、包长等网络元数据仍可见。TLS 提供传输保护，应用层加密不替代 TLS 服务端认证。[RFC 8446](https://www.rfc-editor.org/rfc/rfc8446.html)

### 5.4 网络路径与登录持久性

GUI 插件只请求客户端网络能力，不自行选择 socket 或使用内核 IPC。用户在源设置中选择直连或通过内核；客户端执行并报告失败，不静默切换。

通过内核访问需要已有可用路径。首次没有配置时允许用户选择直连完成初始化；不能让获取首份订阅依赖该订阅先启动。

账号密码仅用于首次或被要求重新授权，不保存密码自动重试。自动续期登录属于 v0.0.1 必须能力，由服务端插件负责：

- 首次授权签发绑定账号、设备和授权代次的会话及续期凭据；客户端通过安全存储保存引用，插件通过受控能力使用。
- 访问会话到期前或重启恢复时，GUI 插件发起续期业务，客户端执行 IO；服务端检查账号、设备、通信开关和授权代次后续发。
- 续期凭据轮换、重放检测及响应丢失后的恢复语义在 P0 固定；同一设备续期合并并发请求，不能因普通网络重试错误注销合法设备。
- 临时网络失败退避，不清除身份或反复要求密码；明确撤销、授权到期或“重新授权”结果使旧续期链终止。
- 服务端清空授权后，续期不能自动恢复设备授权，必须重新通过密码认证。密码重新授权前清理该源旧的会话和续期句柄。

设备授权期限、会话期限和续期策略由插件配置/契约规定，不套用原生 JWT 期限；协议密钥更新不等于用户重新登录。

## 6. ZBoard 嵌入页面与数据边界

### 6.1 设备展示

用户页面只允许读取/撤销本人设备；管理员页面按宿主确认的管理权限读取各用户设备及数量。用户 ID 和管理员身份由宿主 UI 会话注入，不信任 iframe 或客户端自报身份。

设备最小记录：插件记录 ID、用户绑定、源实例、设备公钥/标识、设备名称、授权状态、授权时间、上次成功登录时间/IP、最近活动时间、撤销时间。设备名称和系统信息属于客户端自报信息，不作为可信认证事实。

- 上次登录 IP 由服务端从真实连接及已配置可信代理链提取，不接受客户端上报 IP 或任意 X-Forwarded-For。
- 经过内核代理时，服务端看到的可能是代理出口 IP；页面按“上次登录 IP”展示，不称设备真实公网 IP。
- 周期同步只更新最近活动，不伪造成一次密码登录。
- 设备数默认统计未撤销的授权设备，历史总数另标；撤销保留必要审计记录。数据保留期在阶段 0 固定。
- 私钥、密码、会话秘密和订阅正文不得进入页面桥接、设备表或审计日志。

设备撤销后禁止该设备的会话恢复和订阅获取；客户端收到明确撤销后停止同步并标记关联失效。v0.0.1 不承诺远程擦除已下载的本地配置，或仅靠撤销插件设备就终止节点连接；节点权限撤销由 ZBoard 宿主另行执行。

### 6.2 一键清空授权

- 用户只能清空本人全部客户端授权；管理员可清空指定用户或全站的本插件客户端授权。页面显示影响范围并确认该管理操作。
- 服务端原子递增对应授权代次/撤销边界，立即拒绝旧会话和续期凭据；设备列表标记已撤销，保留必要审计，不靠删除几行设备记录模拟失效。
- 清空和续期并发时，清空前创建或正在签发的旧代次凭据不得在清空后有效。多实例服务端共享权威状态，不能依赖单进程缓存。
- 客户端在下一次请求/核对获知失效，停止受影响源的受认证同步与消息拉取，提示重新授权；不影响别的源。离线客户端不能被宣称已即时收到命令。
- 清空授权不删除 ZBoard 用户，不重置密码、不撤销原生网页登录、不修改原生订阅权益，也不清空通信私钥。密钥轮换是独立管理动作。
- 自动续期只更新续期/活动记录，不覆盖“上次成功密码登录时间/IP”。

### 6.3 消息通知与插件内阅读

```text
ZBoard 插件按用户权限提供公告/站内信
  → GUI 插件经客户端调度和加密网络能力拉取
  → 客户端通知能力投递带来源标识的提醒
  → 用户点击查看
  → 客户端安全导航到该插件、该源、该消息的只读详情
```

- 源配置后才可访问该源消息；需要账号的站内信必须完成授权，公告也服从服务端的实际受众规则，不能默认向所有设备广播。
- 消息 ID、游标和已提示/已读状态按源、账号和消息隔离，有界保存。周期拉取、续期和重启不能重复轰炸；离线恢复按游标补取，首轮历史消息采用摘要或未读数，不逐条弹出。
- 插件请求通知许可，宿主负责系统权限、来源标识、频率和投递；拒绝通知不影响订阅。系统通知默认只显示来源和有新消息，不把站内信全文放到锁屏。
- 点击目标使用宿主登记的插件内部路由及消息引用，不让远端正文指定任意命令、脚本或外部地址。显示前重查源/账号归属；源删除、插件停用或账号切换后旧通知不能打开另一账号内容。
- 阅读详情仅含标题、时间、来源和安全渲染的正文；禁用脚本、嵌入表单和自动加载远端资源。只读已读回执可经专用协议同步，不加入回复、编辑、发送、购买或审批。
- 服务端执行消息受众校验，列表和详情均不可越权。不存在/撤回/无权阅读时显示不可用，不以旧缓存绕过明确撤权。
- 通知和阅读内容同样走加密通信；正文不进入普通日志。账号退出/清空授权后回收该账号消息缓存及待投递提醒，系统已显示的通知在平台支持范围内撤回。

## 7. 实施顺序与验收门槛

### P0：契约与宿主能力盘点

- 盘点客户端订阅读写/调度/配置关联实际调用链，设计普通 URL 到来源类型的兼容迁移。
- 核实服务端插件专用请求路由、内部账号验证、有效订阅查询/渲染、插件自有存储、嵌入页面授权、消息读取、通知与内部导航能力；缺口只增加窄 Host API。
- 固定加密协议、首次信任、设备登记/证明、自动续期、清空授权的并发失效、密钥轮换和防重放；给出双端测试向量。
- 固定设备授权期限、同步频率/退避、保留期、关闭通信后的行为和首个验收平台。

完成条件：字段/错误/权限契约、宿主缺口、来源迁移表、协议测试向量和最小真实联调样例齐全。此阶段不提前承诺现有插件框架已经足够。

### P1：服务端插件和加密设备授权

- 建立同仓双插件结构、独立 manifest/发布资源和配套协议测试；补服务端声明式路由注册、通信开关、密钥生成和安全存储。
- 实现专用加密密码验证、设备登记/证明、会话建立、自动续期与一键清空授权；接窄 Host API，不调用原生公开 API。
- 建立设备数据与用户/管理员页面的后端权限边界。

完成条件：错误密码、错公钥、重放、跨设备/账号、关闭通信、撤销及轮换通过双端协议测试；敏感字段不出现在报文正文、错误与日志中。

### P2：GUI 源与有效订阅选择

- 接客户端网络/秘密/密码学能力，完成源地址配置、远端插件发现、自动服务身份绑定、插件页面密码授权及设备持久身份；不得增加手填公钥或指纹字段。
- 实现直连/经内核选项、账号密码授权、有效订阅列表及选择。账号密码是插件页面的瞬时输入，不进入普通配置或日志。
- 服务端每次查订阅/取内容均按当前账号、设备和权益核对。

完成条件：真实面板完成授权和选择；重启可恢复合法设备身份；无可用内核路径时明确报错；不调用原生登录/订阅接口。

### P3：插件 → 订阅 → 配置

- 引入通用插件来源绑定及迁移，普通 URL 行为保持兼容。
- 选择后关联既有订阅菜单，并经唯一同步入口更新关联配置。
- 关闭 URL 编辑、导入/upsert、其他插件投递等对托管绑定的替换路径。

完成条件：重复选择不重复创建；手动同步更新同一配置；替换 URL、账号、订阅 ID、版本及投递目标均被阻止。只验证关联与通信秘密保护，不声称本地配置不可读。

### P4：周期协同、设备管理与通知阅读

- 客户端周期同步与插件周期核对进入同一调度体系，按绑定去重、取消并核对晚到结果。
- 完成用户设备列表/登录 IP、管理员设备明细和每用户设备数及撤销页面。
- 验证双源隔离、源变更、设备撤销、订阅失效、插件停用、通信关闭、自动续期/清空并发、重启恢复和网络失败。
- 实现公告/站内信拉取、客户端通知、点击跳转插件只读详情、去重与账号隔离。

完成条件：即使 GUI 页面关闭也可周期核对；并发触发只有一次有效配置提交；用户不能越权读设备；登录 IP 和设备数口径正确。清空后所有旧续期链失效且必须密码重新授权；拒绝通知不影响订阅，点击提醒只能阅读正确源/账号的消息。失败不清除无关配置，不擅自重连。

### P5：v0.0.1 联调与交付

- 使用真实双端插件包，跑源配置、授权、设备页面、选择、订阅关联、配置生成、周期更新、自动续期、一键清空重新授权以及通知阅读全流程。
- 采集直连与经内核两条路径报文，确认业务正文密文；检查客户端/服务端日志及页面无密码、设备私钥和会话秘密。
- 检查旧来源迁移、普通订阅回归、重启和插件升级行为，完成所改仓库要求的测试。
- 验证同一市场产品在两端分别选择正确宿主包、签名与兼容性；双端停用不改变宿主原生功能。
- 标记本地普通配置仍可能可读；不把这一限制误报为通信加密失败，也不将首版称为受保护配置版本。

完成条件：真实包、代码 SHA、协议版本、目标平台与验收证据一致。仅验证过的平台声明支持；提交、推送、发布及部署分别记录。

## 8. 统一市场产品与多宿主安装目标

### 8.1 市场定位

市场以插件产品为发现、搜索和详情单位。一个产品声明一个或多个适用宿主，每个目标单独声明安装包、版本、平台/API 兼容性与权限。本插件一个仓库、一个市场产品、两个宿主安装目标；不再分别注册两份重复产品资料。

```text
插件产品（稳定 product ID、名称、发布者、介绍、源码仓库）
  ├─ ZBoard 安装目标 → 服务端包、页面、权限、版本/平台要求
  └─ ZNet Sink 安装目标 → GUI 包、页面、权限、版本/平台要求
```

产品身份与已安装包身份分别建模：产品用于统一展示；安装目标映射现有包 ID、宿主、签名发布者及升级链。不能为了合并产品页面直接改已安装包 ID，造成重复安装或丢失授权/数据。产品名或仓库相同也不能自动证明两个包属于同一产品，映射需要发布者认证与市场准入。

### 8.2 展示范围与执行权限分开

- 发布者声明支持哪些宿主、平台、版本以及扩展贡献；市场描述和索引这些信息，不把业务类型预先限制为登录、面板或配置。
- 展示标签、分类、适用宿主是发现信息；能力权限和可执行扩展点仍由各宿主定义、校验和授权。
- 未知宿主/新目标不应让整个市场目录解析失败；消费端可展示不兼容说明或跳过未知目标，不能执行未知包或授予未知能力。
- 声明跨宿主适用不等于同一字节包可在各宿主运行；仍按签名目标与本地运行时选择产物。统一产品不合并权限。

### 8.3 网站与本地市场共用数据

中央市场保存统一产品注册及可信发布来源；发布仓库提供版本和产物元数据。构建生成可缓存的目录、详情及搜索索引，同时供网页和两端本地市场消费。

网站用于全市场搜索、查看详情与适用范围。可用 GitHub Pages 和自定义域名发布静态站点，搜索先使用构建好的索引，无需为了目录查询增加业务后端。GitHub Pages 的静态托管和自定义域名能力见 [官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

ZBoard 和 ZNet Sink 本地默认筛选当前宿主适用产品，详情展示其他支持目标及配套要求，本地只安装本宿主对应包。网站与本地使用同一注册/发布信息，不分别维护三套插件资料。

### 8.4 同仓发布与迁移

建议插件仓库按 protocol/、zboard/、znet-sink/、tests/interop/ 划分职责，共享协议与测试，分别生成宿主格式的签名包。市场注册一次；各安装目标可以独立发版，共同协议声明兼容范围。一端安装不自动安装或授权另一端。

改造应覆盖中央 schema、校验/提交自动化、发布者元数据、双端目录消费与目标选择。具体版本号在盘点实际已发布格式后确定，不沿用旧文中的 v1/v2 状态推断线上现状。

- 现有单宿主插件可以迁为仅有一个安装目标的产品，保留包 ID、数据、权限及更新链；一般只需更新发布元数据，不因市场改造重写插件业务。
- 多宿主插件增加安装目标及独立产物；协议与双端业务仍按本计划实现。
- 旧宿主目录如需兼容，由统一产品数据生成只读投影，明确过渡范围和退出条件，不能继续人工维护两套源目录。
- 包签名、平台选择、权限声明和宿主生命周期继续沿用；市场统一不等于改造为一个共同插件运行时。
- 市场基础契约先于本插件正式注册固定，网站界面可后续完善，不阻塞双端业务的本地联调。

本次核对发现 `/Volumes/tool/plugins` 已有未提交的提交流程等修改；本轮未修改该仓库。后续实施须盘点现有工作及真实发布目录，避免按本地旧格式直接覆盖。

## 9. 后续版本：在同一路线上增加本地保护

v0.0.1 之后，再实现密文配置存储、受保护材料句柄、按策略禁用读取/导出、内存应用和恢复，以及数据库/WAL、日志、调试、诊断和内核观测出口治理。

保护策略从插件来源沿订阅传递到关联配置，同一同步/合成/应用实现消费政策，不新增“加密订阅专用配置后台”。首版可预留版本化政策字段，但不能用隐藏按钮提前宣告保护。

若未来要求同一订阅从任何入口都不可获取明文，届时同时核对 ZBoard 原生下载链接和其他格式出口；首版不修改这些原生交付政策，也不声称阻断旧链接或已导出配置。
