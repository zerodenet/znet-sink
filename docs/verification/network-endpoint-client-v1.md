# 客户端通用端点管理 V1

对照 Zero `network-endpoint-catalog-v1.md`、`network-endpoint-control-v1.md` 与
`wireguard-1` 对话的当前实现（2026-09-30）。本次只修改客户端。

## 客户端接线

- 专业模式主导航提供独立“端点”页面，资源来自内核目录，不按 WireGuard 协议猜测身份。
  端点生命周期操作不嵌入节点页；切出页面停止轮询并丢弃迟到结果。
  简约模式不暴露该管理入口，隐藏菜单设置也遵循客户端导航契约。
  旧 WireGuard 出站浏览入口和策略组选择保留。未来端点使用同一目录和操作列表。
- Rust 端读取 V1 能力契约再查询，未知/旧内核不试探未声明的端点 API。
  检查快照必需字段和分页游标，拒绝重复 ID；跨内核实例或配置变化时拒绝混合快照。
- 显示配置意图、实际方向、生命周期、健康、代际、意图版本、来源、启动时间、
  已有连接及字节计数、最后错误和公开协议详情；null 表示未提供，0 表示实际零。
- 启停、重启和方向控制使用既有 IPC confirmed executor。
  每个操作都核对实际实例和意图版本；只有 accepted/applied/reconciled 全真才
  宣告成功，并核对返回的启用/方向意图及明确的持久化确认。核心 Admin 校验、
  持久化限制和失败回滚保持由内核执行。
- 开关和方向点击后直接提交，提交中同步禁用控件，直到确认结果和补查完成。
  自动保存到当前配置 ID 的稀疏本地覆盖，不提供“应用方向”或“保存到配置”步骤。
  启用状态、方向分项合并；重启和订阅刷新通过统一配置合成再次应用，不修改订阅原文。
- 客户端只对当前配置规范 endpoints 声明中的资源提供修改；其他/旧角色仍可观测。
  控制请求绑定配置 ID、观测配置版本、内核实例和意图版本；在客户端配置操作锁下执行。
  只有内核明确确认后才保存。失败/未知回执不写本地意图、不自动重试。
  内核确认但客户端存储失败会明确提示“已生效，但本地覆盖保存失败”，不伪报已保存。
- 删除配置时移除其端点覆盖；删除后系统代理重定向失败的恢复路径同时恢复本地覆盖。
  临时 IPC 使用 runtime_only，不调用 source_file 或 clear_overrides：持久性由客户端
  配置合成负责，避免一个字段的保存意外清除另一个字段的覆盖。
- 运行中方向收缩优先读取资源操作能力，回退到 global_limitations。
  不能热关闭的方向以一个客户端动作执行已确认的“停用 → 改方向 → 恢复启用”。
  要求内核已声明原子实例/意图条件和启停操作；缺少时保留限制并提示升级。
  只重建该端点，按钮提示现有连接会中断，不重启整个内核。
- 本地覆盖不改变策略选择。规范 endpoints 中的出站角色补入节点与 DNS 目标，
  仅入站角色不作为出站目标；停用资源仍可保留固定策略选择，准入由内核决定。
- 管理页可见时每 5 秒查询，恢复焦点立即查询。操作中停止补查；客户端 scope
  改变或页面卸载后丢弃迟到结果。先订阅客户端状态再读取基线；状态未确认或
  订阅失败时显示目录但禁用控制。已打开的协议详情随目录刷新；详情查询失败
  隐藏旧数据。操作失败后补查实际结果，补查完成前控制保持禁用；分别保留操作、
  目录及详情错误，不重试修改。

## 交由用户提交的内核评估项

以下是接口边界建议，未修改内核，也不把建议当成现有契约强行实现。

1. 此前提出的原子 expected_core_instance_id 已在当前内核工作树实现。
   客户端现已按 network_endpoint_control_preconditions_v1 条件发送该字段，
   旧内核不发送未知字段；复合方向切换要求此能力。仅接入契约，没有修改内核。
2. 控制文档已说明可运行中撤销入站；如果能力仍声明
   endpoint_live_direction_contraction_requires_stop，客户端会保守禁用所有运行中
   收缩。建议能力声明精确为 endpoint_live_outbound_direction_contraction_requires_stop
   （或发布相应操作级能力），客户端已兼容这一更细的限制。
3. 持久化支持建议声明在资源操作能力中，提供规范来源/是否可写及配置基准方向。
   当前不解析不透明 ID 来推断，也不假定 source_file 一定可用。
4. 当前未提供的 Packet/字节统计与更完整的逐 peer 事实、单独路径管理，均
   需要内核真实观测与执行能力；客户端不填假值，也不制造协议专用命令。

## 完成度核对

| 范围 | 客户端完成情况 | 验收证据/边界 |
| --- | --- | --- |
| 通用目录与观测 | 已接线；不按协议猜测端点 | 旧内核、未来协议、分页、空统计、详情刷新回归通过 |
| 启停、方向、重启 | 已接线并核对确认结果 | 本地状态与浏览器回归；真实 IPC 客户端连接独立临时 mock socket |
| 持久化 | 当前配置本地覆盖自动保存，配置合成重放；启用状态与方向分别合并 | 本地配置合成、序列化、订阅更新与删除回归；不等于已安装客户端验收 |
| 陈旧结果与失败恢复 | 变更 scope/实例后拒绝旧结果；未知操作结果不重发 | 超时后补查、权限拒绝、丢失回执、页面卸载回归通过 |
| 策略组与 DNS 兼容 | 声明的出站角色进入目标集合，入站角色排除 | Rust 回归及原有 WireGuard 节点浏览器回归通过 |
| 新建/删除端点、编辑 peer、单独 PacketRoute 控制 | 当前公共控制契约未提供；不虚构运行时按钮 | 现有配置编辑入口仍可编辑配置；额外运行时能力交由内核评估 |
| 已安装客户端、真实内核与各平台 | 尚未完成实机验收 | 未验证 WireGuard A/B 业务、真实 Admin/回滚/源文件保存、Windows named pipe 或 Linux 原生运行 |

结论：现有 V1 公共端点操作已完成客户端接线和本地回归，不能据此宣告真实
内核联调、已安装版本或跨平台实机验收完成。契约来源为当前内核工作树，
不代表其已发布或本机安装内核已具备该能力。

## 验证边界

自动测试覆盖旧内核、未来协议、能力缺失、陈旧版本、确认证据、方向限制、
查询失败和 scope 切换、协议详情与空统计。浏览器测试使用内核契约 fixture，
不等于真实 WireGuard A/B、TUN、Windows/Linux 原生进程或安装包验收。
本任务不提交/发布/安装客户端或修改运行中的网络设置。

## 收缩方向的一次点击（2026-09-30）

- 原先要求用户手动“停用、修改方向、重新启用”的交互已移除。当前支持安全
  前置条件的内核上，客户端自动串行执行三个已有命令，每一步等待明确确认。
  本地设置只在整个操作完成后保存新方向，临时停用不会写成永久停用。
- 按钮在操作中禁用并显示加载图标；界面只展示最终确认，不提前改变勾选状态。
  原本停用的端点仍停用；热修改允许的入站方向直接修改，不额外重启。
- 单步失败后只在最新观测严格匹配最后确认的资源、实例、配置与意图时尝试补偿。
  不采纳新的版本覆盖其他操作者；丢失回执、实例变化、补偿失败不会伪报恢复成功。
- 补偿使用相同的 Admin 校验、原子实例/意图条件和确认执行器；不是内核原子事务。
  若外部操作介入，客户端可停止后续步骤并呈现实际状态，不能保证跨命令原子性。
- 浏览器预览使用模拟数据；真实内核资源、安装客户端及跨平台运行仍未验收。

- 本轮验收：客户端 Rust 端点相关测试 40 项（含 6 项隔离 socket IPC）、前端状态
  测试 11 项、Chromium 交互 15 项通过；类型检查、前端生产构建、格式和 diff 检查通过。
  第一轮 mock 文件修改位置错误导致检查/浏览器失败，修正后完整复测通过。
  补偿仅针对已收到内核明确失败响应且快照匹配的情况；超时、断连、无效回执即使
  暂时读到旧状态也不声称恢复，不追加修改请求。没有运行真实内核或安装客户端验收。
