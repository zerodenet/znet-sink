# 全局用户端点

专业模式的端点页提供独立用户端点库，当前支持 WireGuard 的名称、私钥、本机
CIDR 地址、多个 peer、公钥、远端地址、allowed_ips、启用状态及入站/出站方向。
私钥使用密码框，仅在编辑中显示输入框；编辑会保留未由表单修改的协议字段。

完整定义保存在客户端 AppConfig.userEndpoints，默认空数组兼容旧配置。
所有来源配置在统一 local_edits::resolve 中先合并全局端点，再应用本地设置；
不写回来源文件或订阅原文。切换配置、重启和订阅更新都会重新合成。
同名且协议定义不同的端点，以及同名的入站、出站或策略组会拒绝合并。
相同定义在内部重复合成时合并为一条，启用和方向以全局用户定义为准。
配置切换或订阅更新引入冲突时会报错，不静默丢弃或覆盖端点。

新增、编辑、删除使用专用客户端命令，不假设内核具有端点 create/delete API。
保存持有配置操作锁并核对端点库版本，防止旧草稿覆盖其他窗口或运行态控制
保存的修改；运行中先通过内核配置校验，然后使用现有 app_config 应用/恢复流程
提交完整有效配置。未运行时保存到本地，下次启动应用。应用不确定时不自动重放。
该流程不是跨磁盘与内核的原子事务；沿用现有存储回滚和未知结果报告。

全局端点的启停和方向控制在内核明确确认后更新全局定义，跨配置保持一致；
来源端点仍使用原有按配置保存的稀疏偏好。旧的按配置同名偏好不会覆盖全局定义。
目录归属和地址解析包含全局定义，仍使用内核提供的不透明资源 ID 执行控制。

删除/重命名前检查保存配置和当前有效配置中的显式策略、路由与 DNS 引用；
不自动删除规则或更改出口选择。不会自动将新端点加入策略组或设为默认出口。
端点入口在专业模式默认可见，保留用户显式隐藏偏好；无内核时也可编辑端点库。

协议扩展与 UI 约束：

- 通用用户端点模型只包含名称、启用、方向与 protocol.type/协议材料；通用卡片和保存事务不读取 WireGuard 密钥、地址或 peer 字段。
- Rust 的用户端点协议适配器登记表返回当前客户端可创建的协议，且按协议分派校验；目前仅登记 WireGuard，不展示尚未实现的协议。
- 创建弹窗使用已有 FieldSelect 展示后端返回且具有编辑表单的协议。WireGuard 表单和 peer 输入独立于通用编辑器；编辑既有端点时协议固定。
- 后续协议需登记后端校验与前端表单适配，并接入真实内核契约；保存、版本检查、全局合并、卡片、删除及应用流程复用。
- 输入框、开关、选择器和弹窗使用项目 ui 组件与主题 token；遵循 Svelte 5 bindable 所有权。未知协议保留材料，缺少编辑器时明确提示，不尝试套用 WireGuard 字段。
