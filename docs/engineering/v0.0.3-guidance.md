# znet-sink v0.0.3 工程指导｜评审草案

**范围：桌面端重构。** v0.0.2 RC 线只接缺陷修复，不带入新架构、新配置格式或界面重做。移动端代码保留，暂停新适配；共享模块改动保留已有回归保护，不要求移动端发包或真机验收。

## 1. 工作在哪儿做

- **云端主做**：分支、变更、可复现的测试和 PR。现有名为 `znet-sink` 的云端配置默认检出 `main`，启动时先核对远端及提交，再明确从 `develop` 建重构分支，不能直接在默认分支开工。优先保持一个待验收 PR。
- **本地／目标系统专做真实验收**：安装包启动、真实桌面交互、系统代理/TUN 授权、断开或失败后恢复。macOS 本机结果不代替 Windows、Linux；测试接管用隔离环境，不改日常用机的网络作为默认测试路径。
- 云端结果按“代码检查、模拟交互、真实环境”分别汇报。没跑就注明，不能用构建通过代替联网或视觉验收。

## 2. 规则怎么写、怎么执行

采用 [Lauren Tan 演讲](https://www.youtube.com/watch?v=O_zcc6Xl12g) 的做法：**先用架构减少误用，再用检查挡住可复现的错误，最后才用提示词补充需要判断的事。** 不照搬对方的框架禁令，也不把“让 AI 多写 PR”当成产出目标。

- `AGENTS.md`：只保留范围、依赖方向、入口命令、交付要求及详细规范链接。现有文件主要是栈与命令说明，建议补约束，不另维护一套重复命令。
- 项目规范：解释边界和理由；既有 `CLAUDE.md` 有重叠内容，后续以链接复用，不维护两套不同政策。
- 代码和 CI：真正负责拦截。能由接口收口的，不先写 lint；能做行为反例的，不只搜字符串。改检查器、流程门禁或验收用例，需要说明为什么、展示原反例仍能被挡住，独立人工审阅。不把“现有分支保护已经强制”当作已验证事实。

## 3. 第一批只锁三件事

| 约束 | 放在哪里 | 验收反例 |
|---|---|---|
| **订阅只提供网络配置，不能改界面。** 本地界面设置和网络配置各有入口；显示／隐藏菜单也不等于获得权限。 | 订阅解析输出限定为网络数据；本地 UI 设置独立；复用并补充已有交互面与能力边界检查。 | 一份订阅包含模式、布局或工具开关字段，导入和刷新都不能改变界面偏好或授予能力。允许拒绝不合规输入，但不能静默扩大权限。 |
| **保存、应用和已确认生效分开。** 全局设置与方案内修改各有归属；两种模式共用配置和状态。 | 组合、校验和应用由共享后台负责；界面只发操作、展示状态。用现有工作区、订阅与跨模式回归扩展测试。 | 切模式不重连；坏配置不替换当前有效方案；应用回执丢失显示未确认，不假装成功、不盲目重放。 |
| **桌面重构不得带坏升级路径。** 使用脱敏的 v0.0.2 配置样本，不使用真实订阅凭据。 | 首个可运行 PR 就跑旧配置升级和桌面冒烟；修改共享接口继续跑现有移动回归，必要时补薄适配，不另写一套业务。 | 升级后订阅和本地覆盖仍在；模拟接管失败后应用状态与恢复动作一致；真机未测的项目明确列出。 |

## 4. 验收怎么跑

已有命令：`pnpm verify`（前端、Rust 和 diff 检查），`pnpm test:ui-browser`（独立浏览器测试），`pnpm test:config-workspace`、`pnpm test:cross-mode-state`、`pnpm test:tun-recovery`（定向回归）。`pnpm verify:bundle` 是无签名打包检查，不等于发行验收。默认复用 CI；首轮不凭空造第二套 `check`。

每个 PR 写清四项：**改了什么、哪条反例证明问题、实际跑了哪些检查、还有什么没验证**。改交互者附一条成功路径和一条失败／恢复路径的截图或录屏。不为了绿灯删除失败断言、加忽略、吞错误或放宽超时；测试确需更新时，写清合同变化及证据。

## 5. 第一笔 PR 的边界

本批补充 `AGENTS.md`、本规范及两条配置入口反例：Clash 转换不采纳界面字段，Zero 原生配置校验拒绝界面字段。两条用例由现有 Windows Rust 测试与 Release 订阅回归覆盖，不新增工作流。完整的导入、刷新与界面偏好验证留给后续端到端测试，不由这两条用例代替。第一批不改桌面布局、不换框架、不恢复移动开发，也不把 RC 发版并发修复混进来。

下一个里程碑才开始最小真实链路：**导入旧版兼容配置 → 开启代理 → 改一项配置 → 确认实际生效或明确失败**。先让这条链路跑通，再铺专业页面。
